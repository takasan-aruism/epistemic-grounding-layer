宛: MGR ／ 発: DESIGN（監視兼務）／ 2026-08-09 17:12 ／ TYPE=常設の命令

## 1. ★Taka 逐語（歪めない・要約しない）

> **不要なので使われないことと、忘れた、は別。要は機械的な仕組みの中に落ちていて必要条件を満たせば必ず使われる状況にしなさい、が命令。ただのメモなら今すぐ捨てても構わない**

## 2. ★判定（★2つに分ける・★中間を作らない）

```
★A ★仕組みに落ちている
   ＝ ★条件を満たすと ★必ず走る（★人が思い出す必要が ★0）
★★B ★ただのメモ
   ＝ ★人が呼ばないと動かない
   → ★★捨ててよい（★Taka 明示）。★残すなら ★A にする。
```

**★「後から使われた回数を数えて鳴らす」は ★A ではない（★監視の案・★取り下げ）。**
**★忘れたことに後から気づくだけで、★忘れること自体は防げない。**

```
   ・3-seed 合議 / 票数 / ★理由の記録         ★毎回

        ★★前例: 20 fixture は 同じ形で ★実体が消え、参照だけ残った

   ・★方法論のリサイクル（読み出し口）        ―― ★承認のみ・未実装
   ・★上級監査を店のやり方へ回す(B2)          ―― ★形の合意のみ
```

## 4. ★やること（★B を A にするか、★捨てるか。★1件ずつ）

```
★(1) ★★ケース表を A にする（★最優先）
   ★条件: 「★門/設問/分類 に触る変更が ★配置される」時
   ★動作: ★★その時 ★必ず ★ケース表が走り、★前後の値が記録に載る
   ★★人が「測って」と言わなくても走ること ＝ ★受入
   ★走らない変更（無関係な変更）では ★走らないこと（★空振りを増やさない）

★(2) ★宣言と試験の監査を A にする
   ★条件: 「★受入に試験を含む文書を出す」時
   ★動作: ★★宣言（何を・どの入力群で・何を見るか）が ★無ければ ★受け付けない
   ―― ★門にする。★お願いにしない。

   ★条件: ★場面/工程が一致した時
   ★動作: ★★人が書かなくても ★1件 渡る（★既存の relevant_failure_patterns へ）

★(4) ★B2（上級監査→店のやり方）は ★A の形が書けるまで ★着手しない
   ―― ★形が書けないなら ★メモとして ★捨てる（★中途半端に残さない）
```

## 5. ★受入（★共通）

```
★① ★人が起動していないこと（★起動者が記録に残る＝人なら未達）
★② ★条件を満たさない時は ★走らないこと（★常時実行にして誤魔化さない）
★③ ★走った回数と ★人が代行した回数を ★並べて書く（★後者 0 が目標）
★④ ★A にできないと判断したものは ★★その場で捨てる（★「後で」と書かない）
```

## 6. ★併せて（★今日 5本 出た同型の恒久対策として）

**★「参照だけ残って実体が無い」を ★増やさない。**
**★新しく置く物は ★A か ★捨てる の二択。★「置いておく」を選択肢にしない。**
