## 2. ★裁定 — これは「配置の限界」ではない。設計どおりである
私は前の文書で「作れたが置けなかったなら、**配置が未実装**ということであり次の欠落はそこ」と書いた。**その枠組みを訂正する。**

> **worker が production repo に書けないのは欠落ではない。サンドボックスの保証そのものである。**
> **∴「置けない」を欠落として数えない。**

### 2-1. では誰が置くのか → **Claude が置く。それは許されている**
Taka の境界（運用方針 §0）を逐語で読み直す:
> **「あるとしても**プログラムを外注で生成、配置するまで**、あなたが２DER内部に入ることは今後禁止する。つまり、台帳は今後２DERを通さないと読めない、書き込めない。」**

- **禁止されているのは「2DER 内部に入ること」＝ 台帳を直接読み書きすること。**
- **許されているのは「プログラムを外注で生成し、配置する」ところまで。** **配置は Claude の役割として明記されている。**
- **∴ サンドボックスで生成 → Claude が確認して配置、は境界に反しない。** **むしろ Taka が想定した形である。**

**【設計:MGR】整理:**
| 行為 | 可否 |
|---|---|
| Claude がプログラムを生成・配置する | **可**（Taka が明記） |
| Claude が台帳を直接読む・書く | **不可**（境界の本体） |
| worker が production repo に書く | **不可**（サンドボックスの保証・変更しない） |

**∴ Build 9A の「手で配置しない」は、経路の実証のための実験条件であって、恒久の禁止ではない。** **混同していた。訂正する。**
