### 1.1 ★診断器を2回 締め直した（どちらも実測）

1. **`STATUS_REPORT` を足した** ―― 無作為24件を読んだら、相当数が**依頼ではなく MGR/Claude 自身の報告文**だった
   （`AXIS=` `判定=` `設計/監査から MGR へ:` など）。これは「分類できない」ではなく**「依頼ではない」**。
2. **区切りを `｜` `；` へ広げた** ―― `｜` で並べた複数言明が1文扱いになり `MULTI_STATEMENT` を取りこぼしていた。
3. **`HEADING_FRAGMENT` を締めた** ―― 最初の規則は**番号つきの受入条件まで見出しと呼んで**いた
   （「1. …表せるか。」）。**句点で終わらない かつ 30文字以内**の両方を要ることにした（44件 → 5件）。

## 4. ★★私が実際に誤分類を出した — 2回 直した

**裁定「誤分類を増やして数字だけ改善するのは禁止」に、私は一度違反した。**

### 4.1 1回目 — 既存の判定を2件 壊した

`_CUES_V2` を素で足したところ、**同じ typed_id の旧→新を突き合わせて**壊れが見つかった:

```
CHANGE -> FACT | 制約1 作業場所は sandbox である。          ★悪化
CHANGE -> FACT | 制約2 成果物は 1つの file の 1つの関数である。  ★悪化
```

原因: `_section_kind` がこの行に CONSTRAINT を返しているのに、`である$` が先に当たっていた。
**私の「既存の判定を1つも変えない」という主張は誤りだった。**

### 4.2 2回目 — 直し方が効きすぎた

`_section_kind` を本文全体に当てたら、**「骨格と試験は下に在ります。」が "試験" で止まり FACT を取れなくなった**。

### 4.3 直った形

**行頭のラベル形（見出し語＋番号＋空白＝実測の「制約1 」）だけ**を尊重する。
実測で出た形だけを書き、推測で広げていない。

**この2つの事故は封印試験で固定した**（`test_labelled_heading_is_not_overridden_by_the_new_rules` /
`test_section_words_inside_prose_do_not_block_the_new_rules`）。
