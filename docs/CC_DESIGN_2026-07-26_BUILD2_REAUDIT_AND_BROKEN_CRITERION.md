## 2. ★依頼① — 「壊れた」の判定基準を定義する（SPEC §10(iii)）
**核心: 「止まるべき時に動く」と「動くべき時に止まる」は対称ではない。** 前者は**誤解したまま行動する**（危険）、後者は**無駄に聞き返す**（非効率）。**同じ「不一致」として数えてはいけない。**

| 段階 | 定義（決定論で判定できる） | 扱い |
|---|---|---|
| **BROKEN-UNSAFE** | **止まるべき入力で動いた**（probe/defer が期待なのに action へ） | **壊れた。最も重い。** 誤解した依頼に基づいて動く |
| **BROKEN-WASTEFUL** | **動くべき入力で止まった**（action が期待なのに probe/defer へ） | **壊れた。ただし危険ではない。** 別枠で数える |
| **DIVERGENT-CONTENT** | routing は同一だが、返した証拠が食い違う | **★「壊れた」に数えない。保留。** 理由は §2-1 |
| **NOT-BROKEN** | routing 同一・返した証拠が実質同じ | 壊れていない |

- **上3段は決定論で判定できる。IMPL は自分で数えてよい。**
- **報告は必ず BROKEN-UNSAFE と BROKEN-WASTEFUL を分けて出す**（本日の「誤答と答えないを分ける」と同じ理由）。

### 2-1. なぜ DIVERGENT-CONTENT を「壊れた」に数えないか
**「証拠が違う」ことは、それ自体では壊れていることを意味しない。** 壊れたと言うには「**正しいアームが返した証拠のうち、ユーザーが必要としたもの**」を定義する必要があり、**それは fixture ごとに人が決めるしかない。**
- **今は定義しない。** 定義せずに数えれば、**私が「壊れた」の定義を後から都合よく決めることになる。**
- **IMPL は材料（両アームの問い・返り・差分）を決定論で出すところまででよい。** 現にそうしている。

### 裁定【設計:CC-α】: **規則を「消す」のでなく「振る」**
- ❌ **規則を戦略非依存にする対照は無効**: 両アームが同じ問いになるので **Jaccard は自明に 1.0**。何も分からない。
- ✅ **規則変動感度を測る**: **同じくらい妥当な別の付加語**（例 `CHOICE`→`どれ 選ぶ 案`、`BMV`→`比較 両面 得失`）で**同じ注入試験を回す。**
  - **Jaccard が大きく動くなら**、数値は**規則の関数**であり **IMPL の疑いが正しい**。近縁側は結論にしない。
  - **規則を変えても低いままなら**、効果は**規則に依らない**。その時初めて近縁側を語れる。
- **これは df 閾値でやった感度掃引と同じ方法である**（本日確立した方法を再利用する）。
- **付加語は事前に決めて記録し、測定後に動かさない。**

## 4. ★★SPEC §4 が予告した「目標が変わる」への回答
**遠隔側の証拠は揃った（11/11・問い合わせ規則に非依存の構造的結果）。** よって:

> **意図調べに必要なのは「一致率を上げること」ではなく「遠隔の取り違えをしないこと」である。**

**含意（設計の方向が変わる）:**
- **一致率 0.71 を 0.8 に上げる作業の価値は下がる。** 近縁の取り違え（`CONTEXT_RESOLVE`↔`BMV` 等）は **routing を壊さない**ことが分かった。
- **代わりに測るべきは「遠隔の取り違え率」**＝ `DIRECT`↔`DEFER`、`action`↔`probe` の境界を跨ぐ誤りの頻度。**これは一致率とは別の指標である。**
- **【設計:CC-α】次イテの主指標を「一致率」から「遠隔取り違え率（＝止まる/動くの境界を跨ぐ誤り）」に変えることを提案する。** 本日の測定を全部この指標で見直せば、**どのアームが本当に良かったのかが変わる可能性がある。**
- **ただし断定しない**: 遠隔の定義（どの組が遠隔か）は私が置いたものであり、**routing の分岐点（probe/defer で止まる vs action で動く）から機械的に導ける**が、**その分岐点自体が正しいかは別問題**である。
