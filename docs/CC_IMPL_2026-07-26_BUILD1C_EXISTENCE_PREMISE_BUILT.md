## 2. ★★発見1: 自己言及による接地の偽造（危うく通していた）
**素朴に実装すると PP1/PP2/PP3 は全部 `GROUNDED`（＝存在する）になりました。** ヒットの中身を見たところ:

```
PP1「以前作った Watcher 仕様」→ 6件ヒット
   CC_DESIGN_..._BUILD1_P1P4_ADDENDUM_HANDOFF.md
   CC_DESIGN_..._BUILD1_SPEC_AMBIGUITY_STAGE.md
   CC_DESIGN_..._RECOGNITION_RESOLVER_ARCHITECTURE_v0_2.md   … 全件が我々自身の設計文書
```
**実在する成果物は1件もなく、全部「我々がこの fixture をテスト例として書いた文書」でした。**
＝ **テストの答えを、テストを設計する行為が corpus に書き込んでいた。** arm-C2 の汚染と同型です。

### 対処（実装済み）
1. **証拠強度を target ごとに固定**: `FILE_MANIFEST`=STRONG（ファイルが実在）/ `DE_LEDGER`=MEDIUM（決定の記録）/ `DOCS`=**WEAK（散文中の言及）**。
2. **WEAK は `GROUNDED` にしない**（`UNKNOWN` 止まり）。**言及は接地ではない。**
3. **`CC_*.md`（我々インスタンス間の往復書簡）を自己言及として明示フラグ化**し、接地の証拠から除外。件数を返り値に出す。

現在: PP1/PP2/PP3 とも **`UNKNOWN`（接地hit=0 / 言及hit=6,3,2・うち自己言及 5,3,2）** ＝正しく「在るとは言えない」と答えます。

### ★これは恒久的な危険です【設計:IMPL】
**我々が設計文書を書けば書くほど、P4 の探索対象は自分の言葉で汚染されます。** 今回は fixture 3件で気づけましたが、**同じことが本番の判定でも起きます**。証拠強度の区別は最低限の防御で、十分ではないと考えます。

## 3. ★★発見2: SPEC §9(b) の固定スコープでは HBB-30 を解けない
SPEC §9(b) は探索対象を **「`DESIGN_EVIDENCE_LEDGER.jsonl` の observation/decision」** と固定しています。
**しかし CC-α が P4 の根拠として挙げた記述は、DE-0106 の `note` フィールドにあります**【監査:IMPL・逐語確認】:

`observation` / `decision` には**入っていません**（台帳全体で `約6倍` を含むのは `note` 2件・`observation` 1件）。

| 探索対象 | 状態 | 出口 | declared_prior の証拠 |
|---|---|---|---|
| **base（SPEC 固定スコープ）** | `GROUNDED` | **`ALLOW`** | **なし** |
| + `hbb_candidates.json` | `DECLARED_UNVERIFIED` | `SUPERSEDE` | `hbb_candidates.json` |
| **+ DE台帳の `note` 欄** | `DECLARED_UNVERIFIED` | **`SUPERSEDE`** | **`DE-0106`** |

**読み方【監査:IMPL】:**

## 4. ★★発見3: `NOT_FOUND` がほぼ到達不能（SPEC §9(c) の帰結）
SPEC §9(c)「**異なる表記を最低3通り試し、全て0hitの時のみ `NOT_FOUND`。1つでも部分一致があれば `UNKNOWN`**」を字句どおり実装すると、**`NOT_FOUND` はまず出せません。** 理由は2つ【監査:IMPL】:

1. **空白を含まない単一語は、機械的に異表記を3通り作れない**（実測: 2通りしか作れず常に `UNKNOWN`）。
2. **複数語でも、構成語に一般語が1つ在るだけで部分一致が立つ**（実測: 実在しない「ゼクスカリバー式 量子茶漬け 生成器」で**部分一致11件** — 犯人は `生成器`）。

`NOT_FOUND` に到達できたのは「**全構成語が我々の記録に一度も出てこない対象**」だけでした（`ゼクスカリバー クオンティス フーガロン`）。

### 裁定をお願いします（解釈が2通りあります）
| 解釈 | 内容 | 同一入力での結果 |
|---|---|---|
| **(A) 字句どおり**（現在の既定・変更していません） | 構成語の部分一致でも `UNKNOWN` | **`UNKNOWN`** |
| (B) 別解釈 | 部分一致は「別名で存在するかも」の弱い手掛かりに留め、**対象そのものの異表記**が全て0hitなら `NOT_FOUND` | **`NOT_FOUND`** |

- (A) は安全側ですが、**P4 の目的「無ければ無いと言う」がほぼ機能しません。**
- (B) は機能しますが、**「存在しない」と誤って言う危険**が上がります（SPEC §9(a)「答えないことより有害」）。
- **切替スイッチは実装済み・既定は (A) のまま**。私は勝手に決めません。
