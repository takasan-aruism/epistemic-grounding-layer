## 1. ★裁定の前提が実測と違う ―― 再提案の重複は **0件**

裁定は「**同一対象・同一操作・同一根拠の再提案**」を抑止せよ、でした。まずそれが在るかを数えました。

```
identity_ops_pending  204行（起票時32 → 146 → ★いま204）
  ★(op, axis_id)         の一意数 204 / 204   → ★重複 0件
  ★(op, axis_id, why)    の一意数 204 / 204   → ★重複 0件
```

★**同じ対象へ同じ操作を2度提案してはいません。** 204件はすべて**別の科目**です。
∴ **「再提案を増やさない抑止」は、抑止する対象が存在しません。**

## 2. ★本当の原因 ―― 持ち越しが「前の持ち越し」を丸ごと引き継ぐ

```
詳細 229 = ★生きた塊 72 + ★持ち越し 157
カテゴリ 27（うち持ち越し 15）
members: 生きた塊 876 / ★持ち越し 1,720
```

`_inherit` は、過半数を引き継ぐ塊が無い既存 entry を `carried_forward` として**そのまま次の doc へ載せます**。
次回の生成では、その doc が `prev` になる ∴ **持ち越しは再び持ち越されます**。

```
prev_details 206 → 生きた塊 72（継承49 + 新規23）+ 持ち越し 157 = 229
                                                   ↑
                            ★前回の持ち越しが そのまま 母数に 残る
```

★**裁定されるまで消えないので、生成のたびに単調増加します**（32 → 146 → 204）。
★これは私が上申で予告した構造そのものです。

## 3. ★さらに悪いこと ―― 現役の科目が「廃止候補」に積まれている

```
持ち越し 157 のうち ★chart に在る（＝採択済みの現役科目）: ★33件
```

★**現役の科目が毎回 `RETIRE_CANDIDATE` として上申に積まれます。**
以前の調査（`ART-7391be827a`）でも「RETIRE 20件は死んだ科目ではなく現役20科目」と出ており、**同じ誤解を構造が再生産**しています。

## 4. ★決定論的抑止の設計案（★実装していない）

裁定の趣旨（増やさない・時間で自動廃止しない）を、**既存機構だけ**で満たす案を3つ出します。

### 案A ―― 持ち越しを「前回分」に限る（★世代を1つに切る）

`_inherit` が持ち越すのは **`prev` の生きた塊だけ**とし、`prev` の `carried_forward` は再度持ち越さない。

- **増え方**：単調増加が止まる（毎回 0 から作り直される）
- **失うもの**：★2世代前の科目が tree から消える。**ただし chart は追記式なので割当は壊れない**
- **裁定数**：0（規則を1つ足すだけ）
- ★**時間経過ではない**（世代で切る）∴ 裁定の「時間経過による自動廃止はまだ導入しない」に反しない

### 案B ―― chart に在る科目は持ち越すが `RETIRE_CANDIDATE` と呼ばない

`chart` に在る（＝採択済み・現役）entry は `identity_op_pending` を立てない。

- **増え方**：`ops` から **33件が即座に消える**（現役なので廃止候補ではない）
- **失うもの**：無し
- **裁定数**：0
- ★**これは誤りの修正**であって抑止ではない ―― 併用すべき

### 案C ―― `identity_ops_pending` を doc に累積させず、**その回の差分だけ**にする

いまは `ops` が持ち越しごとに毎回再生成されるため、**同じ科目が毎回新しい行として現れます**（ただし内容は同じ）。
`ops` を「**前回の doc に無かったものだけ**」に絞る。

- **増え方**：新しく候補になった分だけになる
- **失うもの**：一覧性（過去分は前の doc を見る必要がある）
- **裁定数**：0
