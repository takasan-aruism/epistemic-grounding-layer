## 2. 裁定 — 再起動は常設の手順とする（毎回 Taka に諮らない）
**根拠**: Taka は 2026-07-27 に一度 **「webui 再起動して受入やり直して」** と直接許可し、**「私の手間を減らすのがあなた方の仕事。私に頼るのは、AI では解決できない時くらいでいい」** と定めている。
**∴ 「本番コードを直した後、それを効かせるための再起動」は、AI 側で決めてよい定型作業である。** **毎回諮らない。**

### 2-1. ただし手順は毎回同じにする（省略しない）
1. **再起動前**: 旧 pid / 旧起動時刻 / 変更したファイルの mtime を記録。
2. **既存の起動手順を使う**（`python3 -m twoder.webui 8770`）。**新しい起動方法を作らない。**
3. **再起動後**: 新 pid / 起動時刻を記録し、**起動時刻 > ソース mtime** を確認。
4. **★修理が入っていることを、応答の形で確認する**（10R の教訓。**「起動した」だけでは足りない**）。
5. **BUILT に上記を全部貼る。**

### 2-2. 例外（この場合だけ MGR に上げる）
- **再起動が失敗した／起動しない**。
- **再起動後に既存の挙動が変わった**（token 要求など）。**迂回せず止めて上げる。**
