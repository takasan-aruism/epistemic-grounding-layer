## 1. ★先に確かめたこと（★止まってよい場所2 の判定）
```
再現（★ソースを読んだ・★log は読んでいない）:
  webui.py:585 _recv_log() の docstring: 「★これは計器であって台帳ではない ∴ fail-open」
  書き込み先: RUNS / "submit_access.log"
  1行の形  : "<isoformat> RECV /api/submit"
             "<isoformat> SENT /api/submit status=200"
             "<isoformat> SENT /api/submit status=500 error_type=…"
```
| ★問い | ★答え |
|---|---|
| **front door から読むと台帳の直読になるか** | **★ならない。** **★実装が「台帳ではない」と明記している。** ★かつ本 build は**★行そのものを返さない**（§3-2） |
| **∴ 止まってよい場所2 に当たるか** | **★当たらない。★進んでよい** |

### 1-1. ★しかし「1件ごと」には聞けない（★先に出す）
```
★RECV の行に、★依頼を特定する id が無い（時刻とパスだけ）。
∴ ★「私が押した★あの送信は届いたか」は★答えられない。
★答えられるのは「★最後に受けたのはいつか」「★何件 受けたか」までである。
```
> **★これは実装で解決しない。★記録に id が無いからである。**
> **★「あと1段で1件ごとに聞ける」と書かない。** **★id を足すのは別 build であり、★本 build でやらない**（★Taka: 新しい語彙・機構を作らない）。

## 2. ★本 build の一行
> **★「届いたか」だけを返す口を1つ作る。** **★それ以外を返さない。**

## 3. ★作るもの（★1つだけ）
| | |
|---|---|
| **口** | **`GET /api/receipt`**（★名前は IMPL が変えてよい。**★1つだけ**） |
| **認証** | **★既存と同じ**（Basic・`_auth_ok`）。**★新しい認証を作らない** |
| **返り** | **★下の4つだけ**（§3-1） |

### 3-1. ★返す欄（★これだけ。★増やさない）
```
last_recv_at   : 最後に RECV を受けた時刻（★無ければ null）
recv_count     : RECV の件数
last_sent_at   : 最後に SENT を返した時刻（★無ければ null）
last_sent_status: 最後の SENT の status（★無ければ null）
readable       : ★記録を読めたか（true / false）
```
| # | ★守ること |
|---|---|
| **1** | **★「届いたか」以外を返さない**（★依頼文・task_id・状態を返さない） |
| **2** | **★1つの欄が2つのことを指さない**——**★`recv_count: 0` と `readable: false` を★別にする**（★「受けていない」と「記録を引けなかった」は違う） |
| **3** | **★行そのものを返さない**（★log の中身を API 経由で外に出さない。**★数と時刻だけ**） |
| **4** | **★fail-open**（★読めなければ `readable: false` を返し、★500 にしない。**★計器であって台帳ではない**） |

### 3-2. ★なぜ行を返さないか（★理由を書く）
> **★行を返せば、★log を API 経由で読んだことになる。** **★フックが禁じているのは「台帳の直読」だが、★口を作って迂回する形にしない。**
> **★聞くべきは「届いたか」であって「何が書いてあるか」ではない**（★1つの口は1つのことだけ）。

## 4. ★画面（★足すのは1行だけ）
```
※ 2DER に聞いた受信の状態: 最後に受けたのは 2026-07-29T20:44:33 ／ これまでに N件
   （★記録を引けなかったとき）受信の記録を引けませんでした（受けていないのか、記録を引けなかったのかは区別できません）
```
| # | ★守ること |
|---|---|
| 1 | **★「0件」と「引けなかった」を別の文にする** |
| 2 | **★色を使わない。★「正常」「OK」と読める語を使わない**（★0件は良い知らせではない） |
| 3 | **★「1件ごとには分かりません」を1行 添える**（§1-1。**★出せないことを黙らない**） |

## 5. ★変えないもの
- **★`/api/state`・`/api/submit`・`/api/resolve`・`/api/tasks` の返り値**（★1つも変えない）。
- **★集計の母数・和・区分**（Phase 2 で確定したもの）。
- **★EGL を触らない。★新しい台帳を作らない。★勘定科目に触らない。**
- **★新しい完成語彙・保存則・指数・スコアを作らない。**
- **★`_recv_log` の書き方を変えない**（★読む口を作るだけ。★書く側は触らない）。
- **★投入しない。** **★Priority 2〜5 に手を出さない。**

### 6-1. ★受入10 について（★私が確かめられないこと・★先に書く）
> **★我々は log を読めない。** **∴ ★返ってきた値が★正しいかは確かめられない。**
> **★確かめられるのは「答えが返ること」「答えが2つの意味を持たないこと」までである。**
> **★これを BUILT に書くこと。** **★「正しい値が返った」と書かない。**
> **★D-100 で私が書いたのと同じ形である**——**★自分たちの成果を、自分たちで確かめられない。**
