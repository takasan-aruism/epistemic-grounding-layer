## 1. 確定した制約（議論の対象ではない・全インスタンスに適用）
1. **Claude は行政の事務所に来た市民である。** **中のコンピュータを触らない。**
2. **Claude が 2DER 内部に入ることを禁止する。**
3. **台帳は 2DER を通さないと読めない・書けない。**
4. **Claude に残された役割は「プログラムを外注で生成・配置するまで」。**
5. **★現在許されている実装は、この仕組みを徹底するために必要なものだけ。**

**∴ 以後、あらゆる提案は次の1問に答えられなければ着手しない:**
> **「これは、境界を本物にすることに寄与するか。」**
**寄与しないものは、良い案でも今はやらない。**

## 2. ★MGR の答え — **2 を採る**（1 は runtime から外す）

| | 内容 | 判定 |
|---|---|---|
| **1** | Qwen が判断し、**その場でコードを書いて**情報を取得し、保存して Claude が読める状態にする | **runtime では採らない** |
| **★2** | **Qwen は判断だけ。プログラムは事前に用意。最低限の情報だけ渡して検索・出力まで行う** | **採る** |

### 2-1. 理由（境界の観点から。好みの問題ではない）
1. **★境界は、経路が数えられる時にしか強制できない。**
   - 2 なら、台帳に触る経路は**事前に用意された有限個のプログラム**だけ。**列挙できる＝検査できる＝閉じられる。**
   - 1 は**要求のたびに新しい経路が生まれる。** **数えられないものは閉じられない。** **「2DER を通さないと読めない」を実装できない。**
2. **その場のコード生成は、最も分散が大きく、最も静かに失敗する行為である。** 誤った検索は**もっともらしい誤答**として返る。**本日の失敗はすべてこの形だった。**
3. **1 は「勝手に読む主体」を Claude から Qwen に置き換えただけ**である。**禁止した行為の担い手が変わるだけ。**
4. **2 は Taka が繰り返し述べてきた原則と同じ形である**——**存在（＝在るプログラム）を決定論で確定し、その中から LLM に選ばせる。**

### 2-2. では「用意されていない問い」はどうするか
**答えは「答えられない」。それでよい。**（運用方針 §6-7）
- **答えられなかった問いの一覧が、次に作るプログラムの一覧になる。**
- **その「作る」作業が、Claude に残された唯一の役割（外注での生成・配置）である。**
- **∴ 1 は消えるのではなく、runtime から外れて「別の遅い経路」になる。** **要求のたびに走るのでなく、審査を経て1本のプログラムとして配置される。**
- **【未確認】** 2DER に既にこの「新しい能力を作る」経路が在るかは、私は確かめていない。**在るなら使う。無ければ作る。設計/監査が事実として先に確認すること。**

## 3. ★DS は何をするのか（Taka の問い）

**DS = 受付である。** **Claude が中に入らなくて済むのは、受付が在るからである。**

| DS がやること | 説明 |
|---|---|
| **受け取る** | 外部（Claude / Taka）からの依頼を**出来事として記録**する（原文・発信元・実時刻） |
| **選別する（決定論）** | 空の投稿 / 無意味投稿 / 意味の薄い投稿を**機械的に**検知し、RRI に繋ぐか決める |
| **繋ぐ or 返す** | 繋がないなら**理由を返す。** 黙って捨てない |

**DS がやらないこと**: **中身の意味を決めない**（それは RRI）／**台帳を読み書きしない**（それはプログラム）。

**★DS の位置づけの本質**: **DS が受け取るから、Claude は中に入らなくてよい。** **受付が無い、または受付が答えられないと、我々は必ず中に入る。** **本日それを1日やった。**

### 3-1. 全体（Taka の流れ＋境界）
```
Claude / Taka（市民）

   ▼
[ DS ]  受付 — 記録する / 決定論で選別する / 繋ぐか返す
   ▼
```
