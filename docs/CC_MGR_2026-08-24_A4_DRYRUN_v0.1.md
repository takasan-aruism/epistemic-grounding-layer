## 4. ★⑧ 22件を読んで5分類した

★これは私(MGR)の判断であり決定論ではない。

| 分類 | 件数 | 中身 |
|---|---|---|
| **有用** | **17** | その TASK に実際に無かった kind を指した（`would_have_helped`） |
| **正しいが不要** | **5** | 既に在ったものを指した（`3339A186` の GOAL/SPEC/CONSTRAINT、`52892ED3` の SPEC/CONSTRAINT） |
| **誤り** | **0** | ―― |
| **★発明** | **★0** | ―― |
| **判断不能** | **0** | ―― |

### 4.1 ★「発明」が 0 だった理由（構造上の理由）

**この提示器は本文を1文字も作らない。** 返すのは **kind の名前だけ**（`SPEC` / `TEST` / `GOAL` …）で、
「どんな SPEC が要るか」「どんな TEST が要るか」は**一切書かない**。
∴ **構造上、発明のしようがない**。

**「正しいが不要」5件の型**: `missing_rate` は**群の統計**なので、
**その TASK が既にその kind を持っていても提示される**。
∴ **提示側で「あなたは既に持っている」を併記できる**（★未実装・下記 §6）。

## 6. ★③の結論

**→ ★このまま提示器として配線可能。ただし1点だけ足してから。**

**根拠**:
- **発明 0件**（構造上、本文を作らないため）
- **誤り 0件**
- 候補なしを正しく出せた率 **1.000**

**★まだしていないこと（裁定⑩どおり）**:
