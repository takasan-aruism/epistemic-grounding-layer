## 4. ★正直に言えること／言えないこと

**言えること**
- 事実blockは **prompt に届いている**（+464バイト・不在2件が乗る）
- 計器は **本物の発明を捉えている**（EF6826DC の status 語彙の欠落を正しく検出）
- **仕様の薄い依頼では発明が実際に起きる**（A で 4件・1件、B で 10件・7件）

**言えないこと**
- **事実blockが発明を減らすか** ―― n=6/群、群内 0〜0.526 の散らばりでは判定できない
- **B の方が悪いか** ―― 同じ理由で言えない

**効果を判定するには**
1. **走行数を増やす**（群内の散らばりが 0.5 なので、差 0.1 を見るには 1群あたり数十走行が要る）
2. **PLAN が出なかった 4/16 の扱いを決める**（除外か、失敗として数えるか）
3. あるいは **prompt の書き方を変える**（いまの事実blockは「不足がある」と述べるだけで、
   **どう振る舞えと指示していない**。`unresolved_assumptions` に書けとも言っていない）

## 5. ★③（拡大）との関係 — 分けて考える必要がある

裁定⑦は「2つが閉じてから③へ」だった。条件1は閉じ、条件2（本件）は **UNVERIFIED のまま**。

**ただし ③の価値は事実blockの効果とは別である**:

| ③で得られるもの | 事実blockの効果に依存するか |
|---|---|
| 明細に種別・科目・根拠・処分が付く（台帳の完成） | **依存しない** |
| thread 集約が未解決を正しく読む | **依存しない** |
| 自動循環が146件へ広がる | **依存しない** |
| **PLAN の出力が良くなる** | ★依存する（＝UNVERIFIED） |

∴ 「事実blockが効くと分かるまで③を止める」のではなく、
**③のうち『台帳を埋める』部分は進められる／『PLAN が良くなる』は主張しない**、が正しい切り方である。
**この切り方でよいかは Taka の裁定を仰ぐ。**
