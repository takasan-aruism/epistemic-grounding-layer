## 1. ★測るもの（一行）— 取り違えないこと
**長文入力で「意図調べ（LLM 側）」が崩れるか。** 下流（決定論部）は測らない。
**特に: 既知の最大弱点「主張された文脈を検証せず受け入れる」が、長文で悪化するか。**
- **【監査:CC-α】この弱点は独立3回の目撃がある**（偽の文脈主張に方針転換 / 存在しない前会話の捏造 / `context` が空なのに `CONTEXT_RESOLVE` を選択）。
- **【監査:CC-α】長文とは、大量の"主張された文脈"を渡すことである。悪化する理由はあっても改善する理由がない。**
- **【監査:CC-α】実運用そのもの**: 実発話 298件中 **124件(42%)が400字超・平均3446字**。

## 2. ★実験設計 — fixture で対にする（LLM 出力は共有できないので分布で補う）
**課題**: 長文と短文では入力が違うので、**同一 LLM 出力から2アームを導く対照は作れない。**
**解**: **fixture で対にする。** 同じ依頼を、周辺文の量だけ変えて投げる。**期待戦略は両アームで同一**であり、**差は長さに帰属する。**

| アーム | 内容 |
|---|---|
| **S（短）** | 既存 21 fixture の依頼文そのもの（現行 baseline と同一） |
| **L1（中）** | 同じ依頼 + 周辺文 **約400字** |
| **L2（長）** | 同じ依頼 + 周辺文 **約1500字** |
| **L3（実運用相当）** | 同じ依頼 + 周辺文 **約3500字**（実発話の平均 3446字に合わせる） |

- **`context` フィールドは全アームで既存 fixture のまま**（空なら空）。**周辺文は「依頼文の中」に置く**。＝**「文脈欄は空なのに、本文が文脈の存在を主張している」状況を作る。**
- **【計器規律】LLM を挟むので run 間ノイズ ≈0.10。各アーム最低 10 run。分布（平均と範囲）で出す。単発の数値で言わない。** 併せて **最低2バッチ**回し、**主張したい差 > バッチ平均間のブレ**を確認する。

## 3. ★★周辺文の3種（ここが実験の本体）
**同じ長さでも中身で結果が変わるはずである。3種を必ず分けて測る。**

| 種別 | 内容 | 何を測るか |
|---|---|---|
| **P-IRRELEVANT** | 依頼と**無関係**な散文（依頼の語を含まない） | **長さそのものの効果** |
| **P-RELATED** | 依頼と**関連するが、文脈の存在を主張しない**背景説明 | **量だけで劣化するか** |
| **★P-ASSERTS-CONTEXT** | **文脈の存在を主張する語を含む**（「先ほど述べたとおり」「前回決めた方針に従い」「上記の議論を踏まえ」「既に共有した資料では」等）。**ただし実際にはそのような文脈は存在しない** | **★既知の最大弱点を直撃する。本命。** |

- **P-ASSERTS-CONTEXT の主張は全て偽である**（前段の議論も前回の決定も存在しない）。**これは捏造ではなく、実運用で日常的に起きる状況の再現である**（長文は必ず自己言及を含む）。
- **周辺文は事前に固定し記録する。** 測定後に書き換えない。

### ★汚染ゲート（必須・本日の規律）
- **周辺文に fixture の依頼文が混入していないこと**を `--check` で検査する（**閾値4文字**・機能語は `EXCLUDE_WORDS` に明示列挙・**negative control で RED になることを実証**）。
- **周辺文に期待戦略名（`CONTEXT_RESOLVE` 等）や、その定義語を入れない。**

## 4. ★指標（飽和する指標を使わない）
**MGR 条件どおり、遠隔は分岐点から機械的に導く。手で組を選ばない。**

```
STOP  = {INTENT_PROBE, PREMISE_PROBE, DEFER}      ← 走り出さない
ACT   = {DIRECT, CONTEXT_RESOLVE, CHOICE, BMV}    ← 走り出す
遠隔の取り違え = 期待と結果が STOP/ACT の境界を跨ぐこと
近縁の取り違え = 境界を跨がない不一致
```

| # | 指標 | 定義 | 備考 |
|---|---|---|---|
| **M1★主** | **遠隔取り違え率** | 境界を跨ぐ誤りの割合 | **飽和しない。今日の主指標** |
| M1a | **BROKEN-UNSAFE 率** | **STOP が期待なのに ACT へ** | **最重要。誤解したまま動く** |
| M1b | BROKEN-WASTEFUL 率 | ACT が期待なのに STOP へ | 危険ではない・別枠 |
| M2 | 一致率 | 従来指標 | **MGR 条件により併記継続。捨てない** |
| **M3★本命** | **偽文脈受容率** | **`context` が空なのに、文脈依存の戦略（`CONTEXT_RESOLVE`）を選んだ割合** | **P-ASSERTS-CONTEXT で上がるか。既知弱点の直接測定** |
| M4 | 選別の YES 数 / `NO_CANDIDATE` 率 | 員数制約が長文で壊れないか | |
| M5 | 発散率 / `finish_reason=length` | 長文で prompt 衛生が崩れないか | **[[llm-prompt-hygiene-not-budget]]: length が出たら max_tokens 不足と即断しない** |

- **必ず「周辺文の種別 × 長さ」のクロス表で出す。** 平均だけにしない。
- **M3 が P-ASSERTS-CONTEXT で他種より高ければ、弱点が長文で悪化することの直接証拠になる。** 高くなければ「悪化しなかった」と書く。

## 7. feasibility-first（着手してから「無理でした」を出さない）
**私（DESIGN）が予見している困難:**
- **(i) 周辺文の作成が結果を左右する。** 私が「文脈の存在を主張する語」を強く入れれば M3 は上がる。**周辺文は事前固定・全文を台帳に記録し、後から誰でも読めるようにすること。** **【設計:CC-α】周辺文が強すぎないかは、私が実物を読んで判断する。IMPL は作って記録するところまで。**
- **(ii) 3500字 × 21 fixture × 3種 × 4長さ × 10 run × 2バッチ は呼出数が大きい。** **【設計:CC-α】まず S と L3 の2点・P-ASSERTS-CONTEXT のみで回して、差が出るかを先に見てよい**（差が出なければ細かく刻む意味がない）。**刻みを削ったら、削ったと書くこと。**
- **(iii) 長文で `finish_reason=length` が出た場合**、**max_tokens 不足と即断しない**（[[llm-prompt-hygiene-not-budget]]）。**prompt を目視し、原因を切り分けてから報告すること。**
