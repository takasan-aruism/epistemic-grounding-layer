# 材料に「1つのラベルへ 1対1で写る欄」を置かない

2026-08-28 ／ instance=Inference Control
★**この Domain を越えて効く**（Taka 2026-08-28: 「今日出した規則の中で いちばん再利用が効く」）

---

## 0. 規則（1行）

> **分類させる材料に、ある欄の値だけで答えが決まってしまう欄を置いてはいけない。**
> モデルは**分類をやめて転記をする**。しかも**一貫して転記する**ので、安定して間違う。

---

## 1. 実測（同じ失敗を 2回・別の欄で踏んだ）

| 版 | 材料に置いた欄 | 規則に書いた条件 | 標本に占める割合 | 出た結果 |
|---|---|---|---|---|
| **v2** | 一次関数の `指示文の字数` / `promptの出所` | 「0字 かつ PARAM なら PASSTHROUGH」 | **52/56 = 93%** / 46/56 = 82% | **Claude が PASSTHROUGH を 31/56**（gold は2件） |
| **v4** | 呼び手の `書いている文の本数` | 「文を1つも書いていないなら PASSTHROUGH」 | **31/56 = 55%** | **Qwen が PASSTHROUGH を 107/168 = 64%** |

**v2 の欠陥に気づいて材料を直したのが v4。ところが誘導の場所が移っただけだった。**
規則の1行を消しても直らないことは別に確かめてある（Claude は規則なしでも 11/12 が PASSTHROUGH のまま）。

## 2. ★自己一致が上がっても「良くなった」ではない

| | v2 | v4 |
|---|---|---|
| 自己一致（3回とも同じ） | 73% | **82%** |
| 最頻語の偏り | EXTRACT 35% | **PASSTHROUGH 64%** |

**自己一致は上がり、偏りも上がった。** これは**改善ではなく「安定して間違う方向へ動いた」**である。

★**自己一致だけを見て『改善した』と読んではいけない。** 必ず**偏り**と対で見る。
（★この行は Taka の指摘で残した。読みを残さないと次に誰かが同じ誤読をする。）

## 3. 見分け方（★LLM 0回・引く前に見る）

`domain_inference_control.inference_material_health(materials, rules_text, labels)`

| 疑い | 条件 |
|---|---|
| **SUSPECT_FIELD_TO_LABEL** | 退化した欄（最頻値が **40%以上**）の**名前が規則文に出る** = その欄を転記すれば答えが出る |
| **SUSPECT_LABEL_IN_MATERIAL** | ラベルの語が材料の値にそのまま出る = 分類でなく写し取り |
| **SUSPECT_DEGENERATE** | 退化した欄が在る（規則には出ない）= 誘導の芽 |
| **NOT_SUSPECT** | 上が立たない ★「健全」とは言わない = 疑いが立たなかっただけ |

**実発火（過去の材料に当てて確認）**

```
v2 → ★引かない: 指示文の字数=0 が 93% / promptの出所=PARAM が 82% / 答えを読むか=EXISTS が 91%
v4 → ★引かない: 書いている文の本数=0 が 55%
```

## 4. なぜ前段に置くか（費用）

`question_health`（引いた後の検査）は **3回とも引いてから**気づいた（v2 / v3 / v4）。
∴ **4回目も引いてから気づく**。1周の費用は **Qwen 168回 ／ Claude 約20分**。
**前段は LLM 0回**なので、置く方が安い。

## 5. 一般化（他 Domain でも同じ）

「LLM に選ばせる」場面すべてに効く。**材料の欄がラベルの定義文と同じことを言っていたら、それは特徴ではなく答えである。**

- 台帳の分類（勘定科目・種別）
- 依頼の種別判定
- 監査の合否

★ただし**逆は成り立たない**: 退化した欄が在っても、規則がそれを名指ししなければ転記は起きない（v4 の `答えを読むか` は 91% 退化しているが規則に出ないので誘導していない）。**欄の退化と規則の名指しが揃った時だけ危ない。**

## 6. 測っていないこと

- **閾値 40% は 2例（93% と 55%）から置いた**。30% や 50% が正しいかは測っていない。
- 「規則に名前が出る」は**文字列一致**で見ている。言い換え（「文の数」と「本数」）は拾えない。
- ★この規則自体を **別の Domain の材料で試していない**（一般化は 2例＋論拠であって実測ではない）。

## ★成熟度を REPRODUCED から MEASURED へ下げた（同日・自分の門に止められた）

最初 `REPRODUCED` と書いたが、**Domain Manager の昇格条件に引っかかった**:

```
inference_knowledge_maturity →
  LLMK-0007  maturity=REPRODUCED  call_sites=0  ★根拠不足(REPRODUCED を名乗るが呼出点が2未満)
```

昇格条件は「**2つ以上の独立した呼出点**で同じ結論が確認され doc が `call_sites` でそれを名乗る」。
本知識は **呼出点の話ではなく 材料の作り方の話**なので、この条件に合わない。

★**条件の方を緩めなかった。** 緩めれば通せるが、それは
「通したい答えに合わせて条件を歪める」= 今日 私が設問でやった失敗と同じ型である。
∴ **`MEASURED` に下げた**（2版 v2/v4 で再現しているが、条件の形が違う）。

★**残った宿題**: 「呼出点でない知識の REPRODUCED 条件」が **未定義**である。
定義していないので、この種の知識は **構造上 MEASURED より上に行けない**。
★これは欠陥だが、**条件を後から都合よく作らない**ために、いまは未定義のまま残す。
