## 4. ★作る形（★①だけ新規／②③④は既存を呼ぶ／⑤は駆動役と共通）

```
① ★設計図の1行に id を振り、★主張として登記する      ← ★★新規（これだけ）
② ★機械が対応する実物を探す（在る/無い/判定不能）      ← 既存（artifact_registry / 層飛ばし計器）
③ ★在るなら実際に走らせて確かめる                      ← ★既存 conformance_probe を呼ぶ
④ ★結果を設計図の隣に置く（「いつ確認・通ったか」）      ← 既存（台帳へ書く）
⑤ ★機能が増えたら ①へ戻る（2DER 自身が回す）          ← ★駆動役と同じ部品
```

- **★新台帳0**（登記は既存の台帳へ・Taka 常設命令）。
- **★⑤を駆動役と別に作らない。** 駆動役が回す対象に「止まっている依頼」と「設計図の検査」を並べるだけ。
- **★列の信用を分ける**: 構造の列＝機械が出した（そのまま信じてよい）／ 説明の1行＝LLM が書いた（**REPORTED 扱い**）。EGL の格付けと同じ規律。
- **★いちばん効く列＝「最後に動いたのはいつか」**（etrace から機械が出す）。これが在れば**文書が古くなっても嘘にならない**——「ソースに在る≠動く」を文書側で吸収できる。
