## 1. 原則（本日以降、設計の第一原則とする）
> **存在／非存在をまず決定論で確定する。確定した側だけを、それぞれ別の分岐・別の生成に渡す。**
> **LLM に「在るかどうか」を判断させない。選べてしまう時点で選ぶ。**

**型（4段）**:
1. **存在は決定論で出す**（ファイル実体・台帳の登記・admit された事実）。**散文の grep や部分一致で「在りそう」を作らない。**
2. **存在／非存在で分岐を分ける。** 同じ生成器に流さない。
3. **LLM には、存在が確定した側のメニューだけ渡す。**
4. **二択にする**（RRI 4軸7カテゴリの相対選別と同じ。**分かりやすいから間違えない、それだけ**）。

**今日の成功はすべてこの型だった**（後付けで気づいた・記録する）: `CLAIM_STATUS_REGISTRY`（実行時に散文を grep せず、登記したものだけ見る）／ACTION_MENU の `built` を LIVE symbol で機械検証（**「できるつもり」を機械が止めた**）／空入力の入口 reject。
**今日の失敗もすべて同じ型の欠落だった**: 散文が接地証拠になった／報告を書くと母数が増えた／**我々の codegen プロンプトが Taka 発話として数えられた**。

## 3. ★裁定 — Build 3 を差し替える
**Build 3（長文で崩れるかを測る）は実施しない。** 理由は2つ:
1. **前提が消えた**（長文は実発話の 4〜11%・42% は我々のプロンプト混入）。
2. **より本質的**: 弱点は**測る対象ではなく、構造で不可能にする対象**である。**「文脈が無いのに文脈で解決すると言う」は、メニューから外せば起き得ない。**

### 差し替え = **Build 3'「存在で分岐する意図調べ」**
**DESIGN が `★実装源` BUILD_SPEC を1本書くこと。** 骨子（MGR 起草・穴は設計が潰す）:
1. **意図調べの前に決定論の存在判定を置く。** 各戦略に**存在の前提**を対応させ、**満たさない戦略はメニューから外す**（LLM に見せない）。
   - `CONTEXT_RESOLVE` ← **直前文脈が実在する**（`bind_context` が `HIGH/MEDIUM`。`UNRESOLVED/LOW` なら**外す**）
   - 他戦略の前提も**1つずつ表に書く**（**書けないものは前提が無いということ。無いなら無いと書く**）。
2. **外した事実を記録する**（`pruned_strategies` と理由）。**黙って外さない。**
3. **受入（対で出す）**:
   - **(i) 文脈が無い入力で `CONTEXT_RESOLVE` が選ばれ得ないこと**（構造的に不可能＝**LLM を呼ばずに示せる**）。
   - **(ii) 文脈が在る入力では従来どおり選べること**（機能を殺していない）。
   - **(iii) 既存 fixture で一致率・遠隔取り違え率が悪化していないこと**（**分布・paired・ノイズ ≈0.10**）。
4. **feasibility-first**: メニューを削ると `NO_CANDIDATE` が増える可能性がある。**増えたら増えたと出す**（それは「安全側に倒れた」であって失敗ではない・ただし**無駄に聞き返す BROKEN-WASTEFUL** として別枠で数える）。
