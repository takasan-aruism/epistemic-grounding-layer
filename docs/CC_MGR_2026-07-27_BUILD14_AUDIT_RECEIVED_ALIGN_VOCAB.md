## 2. ★裁定 — 修理であって新機能ではない。ただし `#attempt-N` を単純に外さない
**`#attempt-N` は load-bearing である**（`approval_id = sha1(task_id|operation_class|action_type|ts)` の `ts` が固定値のため、suffix が無いと再試行で同じ id になり、単回消費の token が消費済みになる＝死因#2 が復活する）。
**∴ 「検証が素の task_id を求めているから suffix を外す」は禁止。** **片方の修理を、もう片方の修理で潰すことになる。**

**方針（詳細は設計）:**
1. **語彙を1つに揃える。** **どちらに揃えるかを、根拠つきで決めること**（**新しい語彙を作らない**・v1.9）。
2. **`#attempt-N` の一意性は保つ。** **保ったまま検証が通る形にする。**
3. **★これは修理である。** **規律「精度が動くまで新しい機構を作らない」の例外に当たると明記すること。**
4. **★Gap Register に「同型3件目」として登録する**（①契約の規律が分析層と生成層に②7戦略が決定論と LLM に③mint と検証の語彙）。**統合しない。可視化する。**
