## 1. 実装（`/command` の JS のみ。★Python 側は1行も変えない）

### 1-1. 受け口（★最小・既存の初期化に足す）
```
現状（実読）: webui.py:649  let TASK=null, …
             webui.py:763  load();          ← 起動時に走る
             webui.py:665  if(r.task_id){TASK=r.task_id; … return load();}

追加:
  ① 入力欄を1つ足す:  <input id="runid" placeholder="ETR-… で開く"> ＋ OPEN ボタン
  ② 起動時に location.search の ?run=ETR-… を読む。在れば同じ経路で開く
  ★どちらも「TASK を決める既存の道」に合流させる。★別の描画系を作らない
```

### 1-2. 開く手順（★決定論。分岐を推測で埋めない）
```
openByRun(rid):
  1. GET /api/resolve?id=<rid>
     resolved=false → 「その run は記録に無い」と出して終了（★エラー画面にしない）
  2. events から task_id を探す（★最初に見つかったものを採る。複数在れば「複数在る」と出す）
  3. task_id が在る  → TASK=task_id; load();   ← ★既存の描画をそのまま使う
     task_id が無い  → TASK=null;  §2 の「run だけの画面」を描く
  4. ★どちらの場合も ③「通過した処理」カードを run の events から描く
```

### 1-3. ★③ 通過した処理（両方の場合で描く）
```
ts / component / function / result / error を全件。
★truncated が true なら「打ち切られた: total N 件中 M 件」と画面に出す。
★件数を必ず出す（count / total）。
```

## 2. ★埋まらない項目の出し方（MGR 逐語。★文言を変えない）
**`task_id` が run に無いとき、次を★そのまま出す:**
| 項目 | **出す文言** |
|---|---|
| **②** 現在地 | **「この依頼は DW を通っていない。DW 上の現在地は無い」** |
| **④** 根拠と結果 | **id は出す**（`UTT-` / `RSIG-` / `RREQ-` / `RINT-`）。**EGL の `source_refs`/`claims` が無いなら「無い」と書く** |
| **⑤** 欠損・失敗 | **event ごとの `result`/`error` を出す。** **`boundary_failures` は「run からは取れない」と書く** |
| **⑥** 次に誰が何を | **「DW task が無いため、次の操作は記録されていない」** |

### 2-1. ★禁止（MGR 逐語）
1. **★空欄にしない。**
2. **★「DW を通っていない」を欠陥のように出さない**（Taka 正典「会話で済むものなら会話で終わる」＝**正常な形**である）。**赤字・警告色にしない。**
3. **★埋めるために新しい状態や推測を作らない。**
4. **★`task_id` が無いときに `/api/state` を叩かない**（`{"error":"no such task"}` を画面に出さない）。
