# Phase 4(知識化) ── 安定を決めているのは 課題の側だった v0.1

2026-08-25 ／ instance=Inference Control ／ 仕様 §13 Phase 4 + §4(成熟度)

## 0. 何を確かめたか

Phase 3 で 2つの call に大きな差が出た（同じサーバ・同じ `temperature=0`・同じ seed 指定）:

| | `request_type:_chat` | `intent_strategy:_llm` |
|---|---|---|
| 実物での 3seed 安定 | **90%** | byte 7〜8/8 が相違・決定も3種 |
| system prompt | EXISTS | ABSENT |
| 出力 | 閉じた6語から**1つ** | 7戦略から**複数** + 自由文 `reason` |

★2件の対照は **相関であって原因ではない** ∴ 3件目を観察で足すのでなく、**要因を振って**確かめた。

## 1. ★仮説①「system 役 / 定義文が安定を作る」 → 反証された

同じ入力（実物の依頼文10本）・同じ出力形式・同じ runtime で、**prompt の作り方だけ** 2×2 で振った。

| 腕 | system 役 | 定義文(CHOOSE 規則) | 3seed 安定 | 本番Bとの多数決一致 |
|---|---|---|---|---|
| **B（本番）** | あり | あり | **10/10** | ― |
| C | あり | 語の一覧だけ | 9/10 | 10/10 |
| D | user 本文へ | あり | **10/10** | 10/10 |
| A | user 本文へ | 語の一覧だけ | 9/10 | 10/10 |

**∴ system 役も定義文も、安定にも答にも効いていない。** 仮説①は **反証**。

## 2. ★仮説②「出力形式(複数選択+自由文)が安定を壊す」 → 反証された

**課題と出力形式を入れ替えた**（交差）:

| 腕 | 課題 | 出力形式 | 3seed 安定 |
|---|---|---|---|
| arm1 | `request_type` の課題 | **複数選択 + 自由文 reason** | **9/10** |
| arm2 | `intent_strategy` の課題 | **単一選択・理由なし** | **5/10** |
| **arm2′**（交絡を外した） | `intent_strategy` の課題 | 単一選択・理由なし | **3/10** |
| **B′**（同じ入力の対照） | `request_type` の課題 | 本番形式 | **9/10** |

★arm2 の最初の 5/10 には「入力が場違い（報告文が混じる）」が混ざっていた ∴ **引き直した**。
`ほしい` を含む＝**確実に依頼文**の実物10本に揃えて、**同じ入力で両方の課題を流した**（arm2′ と B′）。
交絡を外すと差は **縮まらず 広がった**（9/10 対 **3/10**）。

**∴ 出力形式を「不安定側」に変えても壊れない（10/10 → 9/10）。
逆に「安定側」の形式にしても、課題を替えると半分しか揃わない（5/10）。** 仮説②は **反証**。

## 3. 支持された説明: 安定を決めているのは 課題の多義性

同じ runtime・同じ形式・**同じ入力**で **9/10 対 3/10**（交絡を外した arm2′ / B′）。
違いは **何を聞いているか** だけ。

- `request_type` = 「**何を求めているか**」（依頼文に書いてある事を読む）
- `intent_strategy` = 「**どう応じるか**」（読み手が決める事を7つから選ぶ）

これは RRI の K4/K5（犯人は問いの側）と **独立に一致**する。
RRI は依頼文の種別を振って示し、本測定は **課題そのものを入れ替えて** 示した。

## 4. 成熟度（既存の梯子 `twoder/egl_integration.py:17`）

| 知識 | 成熟度 | 根拠 |
|---|---|---|
| system 役 / 定義文は安定を作らない | **MEASURED** | 2×2・10本×3seed・4腕 |
| 出力形式は安定を壊さない | **MEASURED** | 交差 arm1 9/10 |
| 安定を決めるのは課題の多義性 | **MEASURED** | 交差 9/10 対 3/10（同一入力）＋ RRI K4/K5 と一致 |

★**REPRODUCED にしない**。課題ペアが1組・モデルが1つ・標本10本のため。

## 5. 再利用できる形（条件 → 操作 → 結果）

- **条件**: ある LLM 呼出が同じ入力で揺れる。
- **操作**: ★runtime・system 役・出力形式を触る前に、**課題を入れ替えて**測る
  （安定している別の課題を同じ形式で流す／不安定な課題を安定側の形式で流す）。
- **結果**: 実測では **形式側の操作は 10/10→9/10 しか動かず、課題側の操作は 10/10→5/10 動いた**。
  ∴ **効く順は 課題 > 形式 > runtime**。

## 6. 測っていないこと・弱いところ（★はっきり書く）

- ~~arm2 の入力に報告文が混じる~~ → **同日に引き直して解消**（arm2′ / B′。母集団55本の先頭10本）。
  ただし `ほしい` を含むという **表層フィルタ**であり、意味で選んでいない。
- 標本は **先頭10本**（無作為抽出でない）。モデルは 1つ。`claude -p` との比較なし。
- arm2′ の分布は DIRECT 5 / DEFER 3 / BMV 1 / PREMISE_PROBE 1 ―― **依頼文なのに DEFER が 3件**。
  ★DEFER の定義（不正形・解釈不能）と実物のずれは **別に測る必要がある**。
- 「課題の多義性」を **測る計器はまだ無い**（今は 2つの課題を比べただけ）。
