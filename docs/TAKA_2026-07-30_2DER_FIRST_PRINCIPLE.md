## 1. ★Taka 逐語（全文）
> 追記：2DER優先原則
>
> Claude Code は、2DER の代わりに作業してはなりません。
>
> 開発中であっても、まず 2DER を使用してください。
>
> 原則は次のとおりです。
>
> 1. まず 2DER を使う。
> 2. 2DER が取得・判断・実行できなかった箇所だけを開発対象にする。
> 3. Claude Code が外側で代行できることは、2DER を使わない理由にならない。
> 4. 開発後は、必ず 2DER を通して同じ作業を再実行し、成立を確認する。
>
> 作業開始時には、必ず次の4点を確認してください。
>
> * 2DER のどの入口を使うか。
> * 2DER で何を試したか。
> * 2DER では何ができなかったか。
> * その不足を補うために何を実装するのか。
>
> 外部処理を行う場合は、必ず「2DER では取得不能・実行不能だった理由」を証拠付きで残してください。
>
> 「Claude Code のほうが早い」「外で調べたほうが簡単」という理由で外部処理へ切り替えてはいけません。
>
> 2DER の目的は、Claude Code が代わりに仕事をすることではありません。
>
> 2DER 自身が仕事をできる範囲を広げることです。
>
> したがって、開発の流れは常に次の循環を守ります。
>
> 2DER を使う
> → 不足を観測する
> → 不足だけを実装する
> → 2DER で再実行する
> → 成立を確認する
>
> この循環を崩して、Claude Code が外側で解決した場合、その作業は原則として 2DER の進捗とはみなしません。

## 4. ★追記（Taka・2026-07-30 03:00）— ★5番目を足して循環を閉じる
> 一点だけ、将来追加してもいいと思う項目があります。
> 今の4項目は 1.どの入口を使うか 2.何を試したか 3.何ができなかったか 4.何を実装するか ですが、最後に
> **⑤ 実装後、2DERだけで再現できたか**
> を加えると循環が閉じます。

**★MGR 判断: 「将来」ではなく★いま入れる。**
> **★理由: 原則④が既に「開発後は必ず 2DER を通して同じ作業を再実行し、成立を確認する」と定めている。**
> **★⑤ は新しい範囲ではない。★既に義務である手順を、★毎回 目に見える欄にするだけである。**
> **★入れないと、今から「将来」までの全文書で、★閉じたかどうかが書かれないまま残る。**

**★5点の書式（★以後これ）**
```
① 2DER のどの入口を使うか
② 2DER で何を試したか
③ 2DER では何ができなかったか
④ その不足を補うために何を実装するのか
⑤ ★実装後、2DER だけで再現できたか
```
**★⑤ の書き方**
- **★「再現できた」と書けるのは、2DER を通して★実際に確かめたときだけ。**
- **★確かめていないなら「確かめていない」と書く。★空欄にしない。★「できるはず」と書かない。**
- **★2DER 自身の実装（画面・記録）でも ⑤ は要る。★「画面に出たか」「記録に残ったか」を確かめる。**
- **★③が「該当しない」でも ⑤ は省かない。★循環を閉じるのは ⑤ である。**
