## 2. 縦串の範囲（thin＝広げない）

## 4. ★★本体 — 意図を故意に誤らせる注入試験
**正常系を1本流しても必要精度は絶対に出ない。**
- **設計**: 同一入力に対し、意図調べの結果を**外部から強制的に差し替えて** RETRIEVE を走らせ、**返りが実用上壊れるか**を見る。
- **★必ず対にする**（[[paired measurement]]・run 間ノイズ ≈0.10）: **同一の意図調べ出力から「正しい戦略」と「誤らせた戦略」の2アームを導出**し、**RETRIEVE の入力と返りを比較**する。**別 run どうしを比べない。**
- **誤らせ方は近縁と遠隔の両方**:
  - **近縁**: `CONTEXT_RESOLVE` ↔ `BOUNDED_MULTI_VIEW`、`INTENT_PROBE` ↔ `PREMISE_PROBE`
  - **遠隔**: `DIRECT` ↔ `DEFER`、`DIRECT` ↔ `INTENT_PROBE`
- **出す結論**: **どの取り違えが下流を壊し、どれが壊さないか。**
  - 近縁の取り違えで下流が壊れないなら、**必要なのは高い一致率ではなく「遠隔の取り違えをしないこと」**になる。**その時は目標そのものが変わる。**
- **【設計:CC-α】これが入らない縦串は目的を果たさない。** 正常系だけの BUILT は受け取らない。

## 5. ★長文入力を必ず計測する（内部矛盾の解消）
- **dogfood ＝我々の開発依頼は一行ではない。** 縦串を流した瞬間に**未検証の長文領域**に入る。
- **かつそこは既知の最大弱点が最も強く出る領域**（**【監査:CC-α】Qwen は「主張された文脈を検証せず受け入れる」＝独立3回の目撃**。長文とは大量の"主張された文脈"を渡すこと）。
- **必ず記録**: **入力長 / 意図調べの結果 / 崩れたか**。**崩れを長文起因と切り分けられるようにする。**
- **黙って走らせて「縦串が動いた/動かない」だけ見るのが最悪。**

## 6. probe → STOP → 再開（本丸・削らない）
- **ユーザーの返答＝「主張された文脈」**である。**聞き返せば安全ではない。**
- **再開時、返答をそのまま文脈として信じない。返答を新しい依頼として再度 意図調べにかける。**
- **【監査:CC-α】(a) により `preceding_utterance_ref` が入るようになった**（`UTT-0739` で確認）。**ただし貯まったのは1件**なので、**再開経路の実データ検証は今回できない。できないことを BUILT に書く。**

## 7. ★`preflight_gate` に触るなら、先に根を直す（MGR 持ち越し2）
**Build 2 で `preflight_gate` を触る場合のみ**、先に以下を入れること（触らないなら不要）:
- **地位の照会を存在ゲートから分離する。** 量的主張・引用された主張 → `CLAIM_STATUS` 照会（存在ゲートを経由しない）／「以前作った X」「その導出」 → 存在ゲート（対象は**導出**であって数値ではない）。
- 根拠: **「約6倍が存在するか」は問いとして成立しない**（カテゴリ取り違え）。**優先表の衝突は2回ともこの根から出た。** これを入れれば §1-1 の patch は不要になる。
- **触らないなら手を出さない**（[[rigor-must-earn-its-return]]）。

## 8. 失敗の記録は必須（オプションではない）
- **`NOT_BUILT` / `BLOCK` / `NO_ACTION` を必ず記録する。**
- 根拠: **【伝聞】** 2DER で実際に効いたのは failure-history retention であり、Taka も「過去引き＝あり」と判定した。**「まだ作っていない」の蓄積が、次に何を作るべきかを決める。**
- **`NO_ACTION` は失敗ではなく発見として記録する**（前者の `NO_CANDIDATE` と同型）。

## 10. feasibility-first（着手してから「無理でした」を出さない）
**実装可能性が低いと分かった箇所は、設計時／着手直後に先出しすること。** 原因と3択（具体提案／上級監査／人間確認）を書く。
**私（DESIGN）が現時点で予見している困難:**
- **(i) 再開経路の実データ検証は不可能**（記録が1件）。§6 のとおり「できない」と書けばよい。
- **(ii) 第2メニューの網羅性**は原理的に「今できること」の写像でしかない。**LIVE 裏付け（§3）で"できるつもり"は防げるが、"できるのに載っていない"は防げない。** 漏れは漏れとして報告すること。
- **(iii) 注入試験の「壊れた」の判定基準**が未定。**【未確認】** 何をもって「実用上壊れた」とするかは、**最初の数件を見てから DESIGN が定義する。** IMPL は**判定基準を勝手に作らず、材料（入力・返り・差分）を決定論で出すところまで**でよい。
