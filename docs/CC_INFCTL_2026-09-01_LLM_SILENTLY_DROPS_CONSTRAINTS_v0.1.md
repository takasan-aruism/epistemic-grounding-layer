## 0. 失敗の型（1行）

★**LLM は「短くまとめる」とき、制約（〜してはいけない）を 真っ先に 落とす。**
★落ちても **出力は正しく見える**（JSON も通る・文も自然）∴ ★**返りを見ても気づけない。**

## 1. 実物（母集団 10本のうち T05）

依頼文には 4つの意図が在った：

1. 4区分に振り分ける LLM を作る
2. ★**ローカルの Qwen を使い、外部 API には出さない**
3. 同じ文3回で3回とも同じ区分
4. 全部を1区分に倒す器より正解が多い

LLM v2（生成＋監査）が出した明細は **2件だけ**：

```
1. 社内の問い合わせ文を4つの区分に振り分ける LLM を作ってください。
2. 受入条件は、同じ文を3回入れて…全部を1つの区分に倒す器より正解が多いことです。
```

★**「外部 API には出さない」が 1文字も 残らなかった。**
★決定論の分割（現行）は 5件に分け、★**その制約を残した。**

★落ちたのが**セキュリティに関わる制約**だったのは偶然ではない
── ★制約は「本題」ではないので、★要約で真っ先に削られる側に居る。

## 2. 分母つき（★測る物を 文字の一致から 意図の登記へ変えた後）

| | 意図が登記された | 偽を「在る」と誤答（★対照） |
|---|---|---|
| 現行（決定論の分割） | **35/35 = 100.0%** | 0/20 = 0.0% |
| LLM v2（生成＋監査） | **33/35 = 94.3%** | 0/20 = 0.0% |

★分母の鍵 = 作文者の意図表 35（母集団10本）／偽 20。
★判定器が落ちた回 = 0/10（両方）。

## 3. ★対策

1. ★**置き換えない。足す。**（Taka 逐語「本文を捨てるわけじゃないので二重管理できりゃいい」）
   原文を正本として残し、★LLM の構造化物は **AI 用の索引**として添える。
2. ★**文字の一致で測らない。**（Taka 逐語「文字の一致率みたってしょうもない」）
   測るのは ★**「頼んだ事が出力のどれかに書かれているか」**＝意図の登記。
3. ★**偽の意図を混ぜる**（本文に書いていない事）。★誤答率が上がったら、器でなく **判定器**が壊れた印。
4. ★配線の前に ★**制約だけを取り出して、残ったかを数える。**
   ★通常の受入試験は「主題が残ったか」しか見ないので、★制約の脱落を通してしまう。

## 4. ★この指標の効く範囲（★隠さない）

- 現行が 100% なのは ★**原文をほぼそのまま分けているから＝天井に貼り付いている**。
  ∴ ★この指標は「良くなった」を示せない。★**「悪くなった」だけを捕まえる。**
- ∴ ★回帰試験（劣化の門）としては成立。★改善の証明には別の指標が要る（★未測定）。
- n=10本・意図35 は小さい。★母集団を増やす手番は立てていない。
