## 2. ★原因（決定論で確定）
```
再現: sed -n '1,12p' ~/.claude/hooks/2der_role.sh
  KEY=$(tty 2>/dev/null | sed 's|/|_|g')
  F="$D/$KEY"

再現: K=$(tty 2>/dev/null | sed 's|/|_|g'); echo "KEY=[$K]"
  → KEY=[tty ではありません]          ← ★日本語 locale のエラー文がそのまま鍵になっている

再現: ls ~/.claude/hooks/.roles/ ; cat -- "tty ではありません"
  → ファイルは1個だけ: [tty ではありません] = MGR
```
> **`2der_role.sh` は「同一端末=同一役割」として TTY を鍵にしている。**
> **★しかし Claude Code の Bash は TTY を持たない。** **∴ `tty` は失敗し、その★エラーメッセージが鍵になる。**
> **∴ 鍵は全インスタンスで同一文字列になり、役割ファイルは★1個しか存在しない。**
> **∴ 最後に `set` した者の役割が、★全員に配られる。** 07-27 16:56 に `MGR` が書かれ、以後 全員が MGR と表示されている。

**★フォールバックも効いていない:**
```
[ -z "$KEY" ] || [ "$KEY" = "not_a_tty" ] && KEY="ppid_$PPID"
```
- `$KEY` は空でも `not_a_tty` でもない（日本語文字列）ので、**`ppid_` に落ちない**。
- **★英語 locale を想定した比較である。** `tty` の英語出力は `not a tty`（空白）で、`not_a_tty` にもならない。**∴ この行は最初から一度も効いていない可能性が高い**（**未確認**: 英語 locale での挙動は試していない。誰が=CC-α / いつ=MGR が要ると言えば）。
