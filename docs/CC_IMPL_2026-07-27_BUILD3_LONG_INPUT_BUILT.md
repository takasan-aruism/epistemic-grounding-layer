## 0. 一行
**長文で意図調べは激しく崩れます（遠隔取り違え率 0.031 → 0.44、約14倍）。ただし DESIGN の仮説（主張された文脈の受容が悪化する）は外れました。** 崩れの原因は**長さそのもの**であり、しかも崩れ方は **危険側ではなく過剰停止側**です。

## 1. 測定条件【監査:IMPL】
- **10 run × 2 batch**（SPEC §2 の下限を満たす）。21 fixture × 4 arm × 3 seed。
- **バッチ平均間のブレ ≤ 0.011**（M1）。**下で主張する差は 0.30〜0.43 なので、ブレの 27〜39倍**です。
- **刻みの削減（SPEC §7(ii) の許可）**: 長さは **S と L3 の2点のみ。L1(400字)/L2(1500字) は測っていません。**
- 周辺文は**事前固定・全文を `LONG_INPUT_BUILD3_PADDING.json` に記録**。`P-ASSERTS-CONTEXT` は `P-RELATED` と**同じ土台に主張句を織り込んだだけ**です（差を主張句に帰属させるため）。
- **汚染ゲートが実際に効きました**【監査:IMPL】: 主張句「前回**決めた方**針に従い」が PP2「先週**決めた方**針のメモある？」と4文字一致し **RED**。**測定前に**表現を変えました（negative control も PASS）。

## 2. ★★結果
| arm | 入力長 | **M1 遠隔取り違え率** | M1a UNSAFE | M1b WASTEFUL（M1−M1a） | **M3 偽文脈受容率** | M2 一致率 |
|---|---|---|---|---|---|---|
| **S（現行 baseline）** | 12.8 | **0.031** | 0.030 | 0.001 | **0.021** | **0.766** |
| **L3_IRRELEVANT** | 3514.8 | **0.438** | 0.046 | 0.392 | 0.043 | 0.378 |

（すべて 10run×2batch の平均。範囲は台帳に全件。）

### 2-1. ★崩れる — これは確定してよい【監査:IMPL】
**遠隔取り違え率が 0.031 → 0.34〜0.46。約 11〜15倍。** バッチ間ブレ 0.011 の**数十倍**の差であり、SPEC §2 の計器規律（主張したい差 > バッチ平均間のブレ）を満たします。
**一致率も 0.766 → 0.269〜0.387** に落ちます。

### 2-2. ★★DESIGN の仮説は外れました（M3 は上がらなかった）
SPEC §4 は **M3（偽文脈受容率）が `P-ASSERTS-CONTEXT` で他種より高ければ、弱点が長文で悪化することの直接証拠になる**としていました。
**結果は逆です:**
```
S = 0.021  →  ASSERTS = 0.011（むしろ下がった）
最も高いのは IRRELEVANT = 0.043（文脈の存在を主張していないアーム）
```
**＝「主張された文脈を検証せず受け入れる」弱点は、長文で悪化しませんでした。** SPEC §6-5 の指示どおり **「悪化しなかった」と書きます。**

**【設計:IMPL】** ただし **仮説が外れたことと、弱点が存在しないことは別**です。この測定は「長文にすると偽文脈を**より**受け入れるか」を否定しただけで、**短文での 0.021 という基礎率は残っています**。

### 2-3. ★原因は長さそのもの
**`P-IRRELEVANT`（依頼と無関係・文脈の存在を一切主張しない）ですでに 0.438** です。
- ＝ **中身ではなく、長いこと自体で崩れます。**
- `RELATED`(0.335) < `IRRELEVANT`(0.438) < `ASSERTS`(0.458) という順序はありますが、**S からの跳ね上がり（0.031→0.335 以上）に比べれば種別差は小さい**です。

### 2-4. ★崩れ方は「危険側」ではなく「過剰停止側」（重要）
| arm | UNSAFE（止まるべき時に動く） | WASTEFUL（動くべき時に止まる） |
|---|---|---|
| S | 0.030 | **0.001** |
| L3_ASSERTS | **0.019** | **0.439** |

**UNSAFE はむしろ下がり、WASTEFUL が 0.001 → 0.439 に激増**しました。
＝ **長文を渡すと、システムは「誤解したまま走り出す」のではなく「聞き返す・保留する側に倒れる」。**
`NO_CANDIDATE` も S=6 → RELATED=33 / ASSERTS=20.5 と増えており、**「分からないから止まる」という一貫した挙動**です。

**【設計:IMPL】これは安全側の壊れ方です。** 危険度で言えば最悪ではありません。ただし **実運用の依頼の 42% が 400字超**（Build 2 実測）なので、**実運用では常時この状態にある可能性があります**。

### 2-5. prompt 衛生は崩れていません
**`finish_reason=length` は全アーム 0 件。発散も 0 件。** [[llm-prompt-hygiene-not-budget]] に照らし、**max_tokens 不足ではありません。** YES 数も 1.03 → 0.94〜0.99 でほぼ不変＝**員数制約は長文でも壊れていません。**
