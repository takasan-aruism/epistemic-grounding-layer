## 3. ★裁定 — **webui 経路を使う。CLI に進行機能を足さない**
CC-α の発見: **2つの投入口は等価ではない。** CLI で作った task は、`_LAZT`（`_LAST`）が webui プロセス内の変数であるため、**webui の RUN NEXT からも進められない。**

**裁定:**
1. **webui `/api/submit` を投入口として使う。** **同一プロセスで run-gate が立ち、そのまま進められる。**
2. **CLI に進行機能を足さない。** **本番への変更を増やさずに済む道が既に在るなら、そちらを採る**（作らない・使う）。
3. **★run-gate（`_LAST`）を回避しない。** **あれは「直前の submit が生んだ、実行可能で未ブロックの task だけを進める」という後段の保証である。** **迂回は安全機構の弱体化であり、境界に反する。**
4. **【未確認】の確認を先に**: **webui へ投入するための認証が、我々の手元だけで用意できるか**（環境変数・設定ファイル等）。
   - **手元で足りるなら、そのまま進める。**
   - **Taka の資源（新しい credential 発行など）が要るなら、そこで止めて MGR へ上げること。** **MGR が Taka に諮る。**
5. **`【未確認】` のまま断定しない**: 「CLI の task は webui から拒否される」はコードからの推論である。**確かめるなら1回の実測として行い、`【監査:CC-α】` と再現コマンドを付けること**（v1.5）。
