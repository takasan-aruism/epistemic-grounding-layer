# 設計/監査 → MGR（写: Taka / IMPL）: **D-27 — `cc_register` は無実。原因は `/tmp` に約1000万エントリが溜まっていること**

## 0. 答え（先に）
**`cc_register.py` に欠陥は無い。** **`/tmp` を cwd にすると、`import` が cwd を走査するために止まる。**
**`import cc_register` に限らない。** **`/tmp` から何を import しても止まる。**

---

## 1. 止まっている場所【監査:CC-α・実測】
```
再現: cd /tmp && timeout -s INT 5 python3 -c "import sys;sys.path.insert(0,'/home/takasan/egl/docs');import cc_register"
結果（KeyboardInterrupt 時のスタック末尾）:
  File "/home/takasan/egl/docs/cc_register.py", line 16, in <module>
    import datetime                                   ← ★cc_register 自身の処理ではなく、最初の import
  File "<frozen importlib._bootstrap_external>", line 1679, in _fill_cache
  KeyboardInterrupt
```
**`_fill_cache` は `sys.path` の各ディレクトリを一覧して索引を作る処理である。**
**`python3 -c` は `sys.path` に cwd を含める。** **∴ cwd が巨大だと、最初の import で止まる。**

## 2. なぜ `/tmp` だと止まるのか【監査:CC-α・実測】
```
再現: ls -U /tmp | wc -l
結果: 9,993,591            ← ★約1000万エントリ
再現: ls -U /tmp | sed 's/[0-9a-f]\{6,\}.*//' | sort | uniq -c | sort -rn | head
結果: tmp… で始まる名前が支配的（Python の tempfile 由来の形）
再現: stat（サンプル3件）
結果: 2026-07-24 / 2026-07-26 のものが残っている（★掃除されていない）
```
**∴ `/tmp` 直下に約1000万件。** **一覧に時間がかかり、import が返らない。**

**∴ D-27 の前提「`cc_register` が cwd に依存して止まる」は、原因の所在が違う。**
**★モジュールは無実である。** **`/tmp` から `import json` しても同じことが起きる。**
