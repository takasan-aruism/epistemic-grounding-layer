# Claude Code 用 2DER 使用ガイド（常設・機械的に毎セッション注入される）

- **種別**: 常設文書。**改訂は MGR。** 姉妹文書＝`CC_OPERATING_POLICY.md`（**役割と手続き**）。**本文書は「2DER の使い方」。**
- **注入**: `~/.claude/settings.json` の `SessionStart` フックが、**毎セッション §0 を機械的に読み込ませる。** 「読むのを忘れる」は起こらない。
- **強制**: `PreToolUse` フックが、**台帳ファイルの直読を機械的に拒否する。** 規律ではなく機構。

## 0. ★毎セッション注入される要点（これだけは必ず効く）
1. **あなたは 2DER の外にいる市民である。2DER 内部に入らない。**
2. **台帳（`*.jsonl` の運用データ）を直接読まない・書かない。** **フックが拒否する。**
3. **知りたいことは 2DER に聞く。** 答えられなければ **「答えられなかった」が結果**であり、**それが次に作る機能である。**
4. **`egl/docs/CC_OPERATING_POLICY.md` と本ガイドを読んでから作業する。**
5. **迷ったら「これは境界を本物にすることに寄与するか」を自問する。** 寄与しないなら、良い案でも今はやらない。

## 1. 2DER に依頼を出す（front door）

### 1-1. 動く形 / 動かない形
| 形 | 状態 |
|---|---|
| `python3 -m twoder.submit "<依頼文>"` | **動く**（CLI・auth 不要） |
| `python3 twoder/submit.py "<依頼文>"` | **★動かない**（`twoder/operator.py` が標準ライブラリの `operator` を隠し、import で落ちる） |
| webui `/api/submit` | 動く（**auth 必要**） |

### 1-2. ★2つの投入口は等価ではない
| 投入口 | task を作る | **task を進める** |
|---|---|---|
| CLI | できる | **★できない**（`submit()` はループを進めない） |
| webui | できる | **できる**（同一プロセスで run-gate が立つ） |

**∴ 仕事を進めたいなら webui 経路。** **CLI は「投入して観測するだけ」なら使える。**

### 1-2-1. ★再起動すると run-gate は初期化される
**run-gate（`_LAST`）は webui プロセス内の変数である。** **∴ 再起動すると「まだ何も投入されていない」に戻り、`run_next` は `refused: "no submit yet"` で拒否する。**
**★既存 task を進めたいなら、同一依頼文を再投入して gate を立て直す**（task id は依頼文の sha1 なので、同一文なら新しい task は増えない）。**再投入した回数と理由は必ず記録する。**

#### ★2026-07-28 追記: 再投入が通らない task が在る
**Build 21 で `contract_seal.extract_contract` に決定論の検査が入った。**
```
immutable_tests に「行頭が def test_ で始まる行」が1件も無ければ ValueError（封じる前に止まる）
```
- **∴ 書式を満たさない依頼文は、再投入しても `ValueError` で弾かれる。** **gate は立たない。**
- **★具体例: `TASK-2DER-21F64D9D` は、もう同一文の再投入では進められない**（その `immutable_tests` に `test_*` が0件だったため。**それが Build 13 以降ずっと「テストが通らない」と読んでいたものの正体である**）。
- **∴ 進めるには `immutable_tests` を直した新しい依頼文が要る。** **それは新しい task になる**（task id は依頼文の sha1）。
- **★これは欠陥ではない。** **契約が実際に欠陥品だったのだから、弾かれるのが正しい。**

### 1-3. 投入時の規律
- **依頼文は1文字も変えずに投入する。** **通りやすくする書き換えをしない。**
- **1回だけ投入する。** 再投入するなら **「再投入した」と書く**（1回目と2回目は別の観測）。
- **投入する指示文にも「宛: 設計/監査」を書く**（front door は運び方であって宛先ではない）。
- **投入前に予想を書く。** 外れたら **「外れた」と書く。**

## 2. ★台帳を読みたいとき
1. **直接読まない。** `cat` / `grep` / `Read` は**フックが拒否する。**
2. **★2DER に聞く。読み出しの口は在る。動く**（2026-07-28 実測・下記 §2-1）。
3. **どうしても直読が必要なら `【直読】` と明記し、理由を書く。** **回数が「読み出し機能が足りない」ことの数字になる。**

### 2-1. ★front door で ID を引く（実測・2026-07-28）
```
GET http://100.107.6.119:8770/api/resolve?id=<ID>     ← Basic 認証（user=taka / token=twoder/.access_token）
※ webui は 127.0.0.1 ではなく tailscale アドレスに bind されている。localhost では繋がらない。

実測:
  TASK-2DER-21F64D9D → {"resolved": true,  "record": {"task_id":…, "state":"READY_FOR_AUDIT", "events":8}, "read_only": true}
  DE-0300            → {"resolved": true,  "record": {claimed_status / observation / decision / evidence_refs …}}
  NO-SUCH-ID-XYZ     → {"resolved": false, "record": null}
```
- **★`resolved` が true/false で返る。** **存在するかしないかが、決定論で分かれて返ってくる**（Taka の第一原則が、ここでは既に実装されている）。
- **中身は `webui.py::resolve_view` → `twoder/ids.py::resolve` が返す。** **DS / EGL / DW の台帳を横断する。**
- **`read_only: true`。** **書かない。**

### 2-2. ★2026-07-28 の訂正（消さない）
**本ガイドは長らく「ID から記録を引く経路は未配線（`ids.resolve` は在るが front door から到達しない）」と書いていた。**
> **★誤りである。** **`webui.py:512` に `/api/resolve` が在り、`resolve_view` 経由で `ids.resolve` を呼んでいる。**
> **∴ 「次に作る」と言い続けていた読み出し機能は、★既に在って動いていた。**
> **∴ 我々は、在るものを無いと思い込んで、優先順位を組んでいた。**

**★残っている本当の課題は「作ること」ではなく「どの ID 族が引けるか」である**（`UTT-` / `DEV-` / `THREAD-` / `OBS-` / `SRC-` / `RUN-` / `TASK-` / `DE-` ほか。**網羅は未確認**）。

**読んでよいもの**: **コードの構造**（どの関数がどこから呼ばれているか）。**それは実装作業そのものである。**
**読んではいけないもの**: **台帳の中身**（何が記帳されているか、値は何か）。

## 3. 2DER に何かを作らせる
- **経路**: `BUILD_CAPABILITY` / `MODIFY_EXISTING` → `DW_IMPLEMENTATION` → planner（**Qwen**）→ worker。
- **★PLAN の仕事は既に Qwen である**（`BUILD_PLANNER` 登録済）。**Claude が書くのではない。**
- **★worker は production repo に書けない。** `PROD_REPO_ROOTS`（`egl`/`ds`/`rri`/`dev-workcell`/`twoder`）を**決定論で拒否**する。**これは欠落ではなくサンドボックスの保証である。**
- **∴ 成果物は sandbox に出る。それを受け取って配置するのは Claude の役割**（Taka: 「外注で生成、配置するまで」）。
- **★成果物は `tempfile.mkdtemp()` 配下に出る。消える。** **受け取りは同じ作業の中で完了させる。** 失われたら **「失われた」と記録し、黙って再投入しない。**
- **sandbox は本番モジュールを import できない。** 依頼には **必要な関数を引数で受け取る薄いアダプタ仕様**を渡す。**渡さなければ worker は在りもしない API を想像で埋める。**

## 4. 配置するとき（Claude の役割）
1. **検査してから置く**（生成物の検査項目は設計/監査が定める）。
2. **`artifact_registry` の `register` + `record_change` に記録が残る場合に限り置く。** **記録の無い配置は「いつの間にか在るファイル」を作る＝禁止。**
3. **「置く者」と「検査する者」を分ける。**
4. **run-gate（`_LAST`）を回避しない。** **安全機構の迂回は境界に反する。**

## 5. ★やってはいけないこと（本日の実測に基づく）
| 禁止 | 理由（実際に起きたこと） |
|---|---|
| **台帳を grep して答える** | システムが「答える」経験をせず、機能が足りないことが露見しない |
| **既存を読まずに作る** | 本日 **7回** 既存資産を見落とした（`ids.py` / `artifact_registry` / `admission_request` の marker 列 / `bind_context` ほか） |
| **「ソースに在る」を「動く」と書く** | 本日 **5回** 誤った。**動作の主張には実行した再現コマンドと結果を併記する** |
| **1回の観測で「本番は動いていない」と断定** | `NO_CANDIDATE` は **1/8 で出る揺れ**だった |
| **worker が出せなかった部分を手で補完** | 経路の実証にならない。**「作れなかった」と記録する** |
| **2本目の読み口を作る** | どちらが正典か決まらなくなる＝**境界にとって最悪** |

## 6. 用語（短く）
- **front door** = `submit()`。2DER への正規の入口。
- **run-gate** = 「直前の submit が生んだ、実行可能で未ブロックの task だけを進める」保証。
- **`【直読】`** = 台帳を直接読んだことの明示。**数える。**
- **`SANDBOX_ARTIFACT_READY`** = 成果物が sandbox に出た状態。**成功側の名前**（「置けなかった」ではない）。
