## 1. なぜ条件②を差し替えたか（訂正理由）

旧条件②は **「task → thread は 1対1」という前提**の上に立っていた。**実測でその前提が成り立たない。**

| 実測 | 値 |
|---|---|
| task 総数 | **614** |
| trace file 総数 | **1,412**（投函ごとに `<task_id>-<trace_key>.trace.json` が増える） |
| 1 task が持つ相異なる `RTHREAD_ID` の数 | **0本 327 / 1本 253 / 2本以上 34** |
| 2本以上を持つ task | **34件（5.5%）**。候補の本数は 2/3/4/7/8/9/**11** |
| 最多 | `TASK-2DER-C032596E` = trace file **79本** / 相異なる thread **11本** |

旧条件②の錨のうち:

- `TASK-2DER-B14D7ACA → RTHREAD-6bfd5b30` … **一意で一致**（○）
- `TASK-2DER-C032596E → RTHREAD-53614fdb` … 期待値は **11本の候補に含まれる**が **一意ではない**（判定不能）

**∴ 旧条件②は「錨が壊れた」のではなく「前提が誤っていた」。** 1対1でないものに 1対1の錨を当てていた。

**訂正版が正しい理由**: 依頼書自身が **「意味判断をしない。対応を返すだけ」** と書いている。11本から1本を黙って選ぶのは意味判断である。∴ **選ばずに全部返し、一意でないことを明示する**のが依頼の趣旨に合う。
