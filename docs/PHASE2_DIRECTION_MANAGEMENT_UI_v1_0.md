## 1. 本文（★Taka 逐語）

一方、Phase 1 完了は「一本の道が完成した」という意味ではありません。残件は明確に分けておくべきです。

* 13番目の入口
* Web UIからの ETRACE_RUN_ID 読み出し
* DW枝の到達性確認
* DW fail-open時の欠損可視化
* 帳簿管理UIから一件の依頼を最後まで読める状態
* acquisition固有イベントの必要性判断
* 独立検算の正式な定義

次の段階で最も重要なのは、Event Traceをさらに精密にすることではなく、これを帳簿UIから実際に使えるようにすることです。

当初の目的は、

**何をやっているのか分からないので、帳簿中心の管理UIを作る**

でした。

したがって次の完了像は、
**案件を開く → 現在地が分かる → 通過した処理が分かる → 根拠と結果が読める → 欠損・失敗・未確認が見える → 次に誰が何をするか分かる**

です。

ここから別の監査基盤や規則作りへ横に広がりすぎると、また元の目的を失います。Phase 1 は区切ってよいですが、Phase 2 の中心は「Event Traceを管理UIへ作用させる」に固定した方がよいです。
