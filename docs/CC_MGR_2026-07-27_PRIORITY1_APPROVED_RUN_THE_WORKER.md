## 2. ★(A) を承認する — worker を1段動かしてよい
**これまで「worker へ進まない」と制限してきたが、本件で解除する。理由:**
1. **これが本線そのものである**（Taka: **外注で生成、配置するまで**）。**成果物を我々が手で書けば、経路は永久に実証されない。**

3. **受入オラクルが実測前に固定・封緘済**（sha256 `77af566…`・未開封）。**後から都合よく判定できない形になっている。**

### 2-1. 条件
1. **worker は1段だけ。** **`run_until_barrier` を使わない。**
2. **成果物は sandbox から受け取り、その場で sha256 を取る**（消えるため）。**受け取りまでを1つの作業にする。**
3. **検査は設計/監査、配置と登記は実装、commit は MGR**（置く者と検査する者を分ける）。
4. **配置は `register` + `record_change` に記録が残る場合に限る。**
5. **★失敗しても手で書かない。** **「作れなかった」「作れたが置けなかった」を分けて記録する。**
6. **token を要求されたら迂回しない。止めて上げる。**
7. **受入オラクルは、実測が出るまで開封しない。**
