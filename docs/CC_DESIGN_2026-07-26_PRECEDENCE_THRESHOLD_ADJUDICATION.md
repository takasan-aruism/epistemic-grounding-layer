## 3b. ★MGR の問い「なぜ量的主張を存在照合の対象にしているのか」— 根まで遡った裁定
MGR 指摘: **優先表の衝突は2回とも同じ根から出ている。** そのとおりなので根を書く。

### 根本原因: **2つの違う問いを1つのゲートに載せている**
HBB-30 の入力には**別種の問いが2つ**ある:

| 問い | 対象 | 種類 |
|---|---|---|
| **「その6倍の導出は在るのか」** | **導出 / simulation / metric** | **存在の問い** |
| **「約6倍という主張はどういう地位か」** | **主張そのもの** | **地位の問い（存在の問いではない）** |

**現在の実装は、後者を前者のゲートに載せている。** 抽出された対象が **「約6倍」** になっている。
**しかし「約6倍が存在するか」は問いとして成立しない。** その数値は入力に**書いてある**——存在は自明であり、疑われているのは**導出**である。**＝カテゴリの取り違え。**

**これが2回の衝突の根である**: 量的主張が存在ゲートに載るせいで、量的入力のたびに存在ゲートが二重発火し、優先表と競合する。

### 裁定
1. **IMPL の §1-1 規則は当面の措置として承認する**（§2 のとおり。動いており、狭める方向であり、受入を満たした）。**ただしこれは根の修正ではなく patch である**と記録する。
2. **根の修正【設計:CC-α】**: **地位の照会を存在ゲートから分離する。**
   - 量的主張・引用された主張 → **`CLAIM_STATUS` 照会**（存在ゲートを経由しない）
   - 「以前作った X」「その導出」 → **存在ゲート**（対象は**導出**であって数値ではない）
   - こうすれば **§1-1 の patch は不要になり、優先表の衝突も根から消える。**
3. **今は作り直さない**（[[rigor-must-earn-its-return]]）。**patch が受入を満たしている以上、動いているものを壊してまで今やる理由がない。** ただし **次にこの周辺を触る時（corpus 拡張・新ゲート追加・Build 2 の配線）に、この分離を先に入れる**こと。**本裁定を根拠として参照できるよう記録する。**
