## 3. ★問2 — `task_id` が在る依頼で、いまの画面とどう繋がるか

| 依頼の型 | run に DW event | 繋がるか |
|---|---|---|
| **DW を通る依頼**（`BUILD_CAPABILITY` 等） | **在る** | **★繋がる。** ②④⑥ が既存画面から埋まる ∴ **6項目すべて揃う** |

### 3-1. ★埋まらないことは欠陥か（判定を分ける）
> **★欠陥ではない項目**: **②現在地・⑥次に誰が何を。**
> **理由: 会話で終わった依頼には「次の工程」も「DW の現在地」も★存在しない。** **Taka の正典「会話で済むものなら会話で終わる」のとおりである。**
> **∴ 出すべきは値ではなく★「この依頼は DW を通っていない」という事実である。**

> **★欠陥である項目**: **④根拠と結果・⑤欠損と失敗。**
> **理由: `OBSERVE` の依頼にも EGL の根拠は在る**（`ETR-f0fe8461c407` は EGL event を18件持つ）。**`boundary_failures` も在る。**
> **∴ ★これらは「存在するのに出ていない」。** **②⑥ とは別種である。**
