## 2. ★読む側は追加不要（MGR §3-3 への答え）【監査:CC-α】
```
twoder/ids.py（docstring と本体）
  ART-  →  twoder.artifact_registry.resolve
  CHG-  →  twoder.artifact_registry.resolve_change
```
**∴ 文書を登記すれば、その `ART-xxxx` は既に正典 resolver で解決できる。**
**∴ 優先度1（front door → `ids.resolve` の配線）が入った時点で、文書も front door から引ける。**
**∴ 「読む側を別に作る」必要は無い。** **むしろ作れば、また繋がらないものが増える。**

## 3. ★Taka の求める形との差（feasibility-first・先に出す）

**Taka**: 「**2DERに登録したので2DERを叩いて設計書を読んでください**」

| 段階 | 何が返るか | いつ可能か |
|---|---|---|
| **(1) 登記** | — | **今日できる** |
| **(2) 2DER が「どこに何があるか」を返す** | `ART-xxxx` → `{relative_path, content_hash, git_blob_sha, current_git_commit, supersedes, …}` | **優先度1 と同時** |
| **(3) 2DER が本文を返す** | 文書の中身 | **★機構が無い。別途要る** |

**∴ (2) までなら「2DER を叩いて設計書の所在と版を得る」ができる。** **本文は、返ってきた path を我々が開くことになる。**
**∴ それは「検証されたポインタ付きの直読」であって、「2DER が読ませてくれた」ではない。** **★この区別を消さない。**

### 3-1. (3) をやるべきか（私の見解）
**今はやらない方がよい。**
- **(2) だけでも大きく変わる**: **どれが正典で、どれが SUPERSEDED で、いま在るファイルが登記時と同じ内容か**（`content_hash`）が、2DER 経由で決まる。**本日「どの SPEC から作るのか」で2回混乱した問題は、これで消える。**
- **(3) は本文を運ぶ機構であり、`_CATALOG` に「文書本文を返すプログラム」を置く話になる。** **優先度1 が通ってから、同じ形で足せる。**
- **∴ 順序は (1)→(2)→(必要なら)(3)。**

## 4. 登記の単位（MGR §3-2）
| | 設計 |
|---|---|
| **単位** | **1文書 = 1 `ART-`**。id は `sha1(repo\|relative_path)` で**パスに対して安定** |
| 改訂 | **再登記**（append-only・latest-wins）。**版を切らない。** 内容が変われば `content_hash` が変わる |
| 上書き関係 | **`supersedes` に旧 `ART-` を入れる。** **我々の `BUILD_ROLE: SUPERSEDED by …` を、そのまま機械可読にできる** |
| 「1問い合わせ=複数明細」との整合 | **文書は伝票（1件）。** **中の節を明細にするのは別の設計**（D-13 系）。**今は入れない。** **1文書=1件で始める** |

**★`supersedes` が在ることの意味**: **今日、私は SUPERSEDED な SPEC を2本作った**（Build 9・Build 9A）。**BUILD_ROLE 行を人間が読む規約でしかなかったものが、登記すれば機械が答えられる。**

## 6. ★誰が登記するか
**書いた者が登記する。**
- **これは「配置は Claude の役割。ただし `register`+`record_change` に記録が残る場合に限る」という既存の裁定と同型である**（`..._STOP_ENDORSED_PLACEMENT_IS_CLAUDES_JOB.md`）。
- **∴ 新しい権限を作らない。** **文書の配置＝プログラムの配置と同じ扱い。**
- **【設計:CC-α】ただし front door 経由ではない。** **`register()` の直叩きである。** **これは「内部アクターでなく侵入」の形に当たる。** **∴ 優先度1 の後、front door 経由に寄せるべきかを別途判断する。** **今は正直にそう書いて始める。**

## 7. ★「登記した」と「読める」を混ぜない（MGR §3-5）
> **登記しても、読めるようにはならない。** **優先度1 が入るまで、我々は file を直読し続ける。**
- **登記の効果は「所在と版が機械可読になる」ことだけである。**
- **∴ 登記を始めても、`【直読】` の数は減らない。** **減るのは優先度1 が入ってからである。**
- **★「2DER で管理されるようになった」と書かない。**
