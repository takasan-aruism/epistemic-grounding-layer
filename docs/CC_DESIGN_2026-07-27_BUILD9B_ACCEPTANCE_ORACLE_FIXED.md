## 3. ★見つかった穴は、成果物の穴ではなく **私の依頼文の穴** である（2件）

### 3-1. P1 — 「未対応接頭辞では `resolve_fn` を呼ばない」を書いていなかった
**存在／非存在を決定論で先に確定し、確定した側の分岐にだけ渡す**——これは Taka の第一原則であり、本 build の動機そのものである。
**しかし私の依頼文は、これを1文字も書いていない。** 書いたのは「接頭辞が含まれない場合 `NOT_ANSWERABLE` を返す」だけで、**先に `resolve_fn` を呼んでから判定しても、返り値としては同じになる。**

**∴ この項目を合否に数えない。** オラクルでは `MUST` から `PRINCIPLE` に落とした。
> **落ちたら成果物の欠陥ではない。私の記載漏れである。**

**★これは今日私が批判したのと同じ誤りである**——**擁護できる別解を、書いていない基準で不正解にすること。** **自分でやりかけた。**

### 3-2. U — `resolve_fn` が例外を投げた場合を定義していなかった
**素直な実装（`ref_good.py`）ですら、この項目では例外が素通りする。** **∴ これも合否に数えない。**
**`ids.resolve` は内部で `except Exception: return None` を持つ**（`twoder/ids.py`）**が、それは呼ばれる側の実装であって、アダプタの契約ではない。**

### 3-3. 依頼文は今回は直さない
- **既に投入されている可能性がある。** **直して再投入すれば、1回目と2回目は別の観測になる**（MGR 条件）。
- **∴ 今回は直さない。** **P1 と U は「次の依頼文に明記する」として持ち越す。**
- **★穴が見つかったこと自体が収穫である。** **成果物を見る前に見つけたので、成果物のせいにせずに済んだ。**
