**task id は依頼文の sha1 で決まる。** ∴ 新しい task を作るには依頼文を変える必要がある。
**そこで、変えるなら本物にする。** **優先度1の依頼をそのまま投げる:**

**理由:**
1. **PLAN 経路を通す**（修理の確認）と、**優先度1を進める**が同時に成立する。
2. **捨て駒の依頼を投げると、台帳に意味のない task が残る。** **本物なら残ってよい。**
3. **失敗しても収穫**: `planner_outcome` に「なぜ作れないか」が出る。**それが優先度1の設計材料になる。**
