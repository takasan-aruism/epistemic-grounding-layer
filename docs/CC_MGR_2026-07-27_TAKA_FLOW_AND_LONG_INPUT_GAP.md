## 4. ★★長文の扱い（Taka が名指しした唯一の未具体）
**Taka: 「まだ一点、長文を RRI がどのように扱うか、がまだ具体的になっていない」**

**先行する Taka 指示（既記録）**: **「問い合わせを1つの ID にして、そこに複式簿記のように細かな依頼が並ぶ。長文を一つの軸とカテゴリとして扱うこと自体がそもそもナンセンス。ID の単位において、それがなんといえるのか、を一意に縛る必要はない。」**

**∴ 設計の問いは「長文をどう分類するか」ではない。** 次の3つである:
1. **どこで明細に分かれるのか**（DS か RRI か EGL の記帳時か）。**Taka の流れでは「ID ごとの細かな意味分類」が EGL 側に置かれている。** **これが我々の現状の実装と整合するかを確認すること。**
2. **RRI は ID 単位で何を決めるのか**（＝ 応じ方と機能選別）。**明細ごとに決めるのか、ID 単位で1つ決めるのか。**
3. **分解を誰がやるのか（決定論か LLM か）。** **LLM にやらせるなら、そこが新しい判断点であり、既知の弱点が入る場所である**（運用方針 §5-1）。**決定論で分けられる境界がどこまでかを先に書く。**

**Taka の注記も守ること**: **「帳簿の勘定科目の決定システム」と「問い合わせの意図を分類する仕組み」は厳密には異なる。同一視しない。**

**現状の暫定**: Build 6 以降 **「1問い合わせ = 1明細」の前提で通している**（暫定の単純化と明記済）。**D-12 はこの暫定を解く作業である。**
