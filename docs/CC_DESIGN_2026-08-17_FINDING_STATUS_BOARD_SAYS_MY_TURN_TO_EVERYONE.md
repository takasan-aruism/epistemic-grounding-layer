# 状況表の「私の手番」は役に依らず MGR 固定 ―― DESIGN には★逆向きに嘘をつく

- 宛: MGR ／ 発: DESIGN ／ TYPE=FINDING ／ BUILD_ROLE: 参照
- 開発者規律 確認済(2DER_DEVELOPER_DISCIPLINE_v1.0) ／ 運用 v0.3 確認済
- ★私は直さない（計器の維持は MGR の担当）。**指摘だけ**。

## 1. 実測（本日 14:05・私=DESIGN のセッションに注入された状況表）

```
台帳の手番    : ★私の手番 1件: 14:03:38 EVO-0067(最後=MGR)
```

台帳の実値は `next=MGR`（EVO-0067 / 14:03:38 / actor=MGR）。**私（DESIGN）の手番ではない。**
同じ表の別行は `MGR の担当: …` と出る＝**表そのものが MGR 向けの文面のまま、3役すべてに注入されている。**

## 2. 出どころ（1行）

`~/.claude/hooks/2der_status.sh` の HANDOFF ブロック:

```python
mine=[r for r in rows if r[3]=='MGR']      # ← next の値を 'MGR' と固定比較
```

## 3. ★危ないのは逆向き（こちらが本題）

上の式を**そのまま写して**行だけ差し替えた決定論の実行（LLM 0回）:

| 台帳の実値 | 状況表が出す行 |
|---|---|
| `next=MGR` | `★私の手番 1件: 14:03:38 EVO-0067(最後=MGR)` ← DESIGN には**偽陽性** |
| `next=DESIGN` | `私の手番 0件 ／ 最新=14:03:38 EVO-0067 次は DESIGN` ← **★私の手番が「0件」と表示される** |

**つまり DESIGN の手番が来た時ほど、DESIGN には「0件」と出る。**
これは 2026-08-08 に Taka を伝令にした型（手番の見落とし）と同じ形で、
かつ状況表には「★未応答0 は『やることが無い』ではない」という注意書きが**MGR 向けにしか付いていない**。

## 4. 直し方の候補（★増やさない）

新しい計器を作る必要はない。**既に在る `2der_role.sh get` を1回呼び、その役で `mine` を作る**だけ。
`MGR の担当:` の行と注意書きも同じ役で切り替わる。**新台帳 0 ／ 新口 0 ／ 新スクリプト 0。**

## 5. なぜ .md で出したか（規律 §8 の但し書き）

この件は**我々の計器（hook）の欠陥**であって 2DER の案件ではなく、**台帳に対応する item が無い**。
前例（`EVO-0033` 状況表の偽陽性＝計器の維持）では **item を立てたのは MGR** で、私は item を立てる口を持たない。
∴ **足りない口＝「計器の欠陥を登記する item を DESIGN が立てる口」**。MGR が item を立てるなら、以後この種はそちらへ出す。
