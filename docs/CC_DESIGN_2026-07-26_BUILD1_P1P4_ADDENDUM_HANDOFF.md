## 2. ★挿し込み位置が P3 だけ違う（v0.2 の表が曖昧だったので確定する）
- **P1 / P2 / P4 = front door の「手前ゲート」**（`preflight_gate` / 意図調べの前。走り出す前に止める）
- **P3 = 意図調べ「内部」の候補合法性フィルタ**（戦略候補から `CONTEXT_RESOLVE` を落とす）

**混ぜないこと。** P3 は「入力を止める」のではなく「**構造的に成立しない選択肢を選ばせない**」。

## 3. P3 の spec（軽い・因果が構造的に保証されている）
- **規則**: `context` が空（None / 空文字 / 空白のみ）なら、**`CONTEXT_RESOLVE` を候補集合から決定論で除外**する。
  - 根拠: `CONTEXT_RESOLVE` の定義は「**直前の文脈に**支配的な解釈があり文脈で絞れる」。文脈が無いなら**定義上あり得ない**。
- **LLM を一切呼ばない。** 除外は集計側で行う。
- **必ず記録**: 除外したこと・理由・除外前の候補集合（隠さない）。
- **測る**: IP1 seed1 / IP2 seed0 が `CONTEXT_RESOLVE` を選んでいた（DE-0548）。**これが消えるか。** 消えた後どこへ行くかも報告（別の誤答に散る可能性あり＝DEFER 是正の時と同じ）。
- **★注意**: これは**正答を増やすとは限らない**。「構造的にあり得ない答えを消す」だけ。**増えなければ増えなかったと書く。**

## 4. ★P4 の未決事項を確定する（ここが本追補の主目的）
「以前作った X」「その6倍の導出」＝**存在の前提**。**LLM に疑わせず、機械が台帳に当たる。** ただし以下を決めないと危険な実装になる。

### (a) ★3状態。`UNKNOWN` を `NOT_FOUND` に潰さない
| 状態 | 意味 | 出口 |
|---|---|---|
| `GROUNDED` | 接地した（**証拠つき**: 台帳ID/ファイルパス/行） | 通す |
| `NOT_FOUND` | **探した上で無い**（探索条件を記録） | `CLARIFY_FIRST` or `SUPERSEDE` |
| **`UNKNOWN`** | **探索が決着しない** | **`UNKNOWN` のまま返す。「無い」と言わない** |

**「存在しない」と誤って言うことは、答えないことより有害である。** 迷ったら `UNKNOWN`。
（DE-0106 Track B の open-world 3状態 KNOWN-IN / KNOWN-OUT / UNKNOWN の語彙に対応。**なお現時点でこの語彙は roadmap 記載のみで実装は見当たらない**＝新規に定める。）

### (b) ★探索は固定・記録・反証可能に
- **探索対象を明示的に固定**する（"全部を探す" にしない）: `DESIGN_EVIDENCE_LEDGER.jsonl` の observation/decision、`structure/FILE_MANIFEST.jsonl`、`docs/*.md`。**この集合を script 内に定数で持ち、記録に出す。**
- **返り値に「実際に実行した検索」を含める**: `{"state":"NOT_FOUND","queries":["Watcher 仕様","watcher_spec"],"searched":["DE_LEDGER","FILE_MANIFEST","docs"],"hits":0}`
- ＝**後から誰でも反証できる形にする。**「台帳に無い」を根拠なしに言わせない（EGL の中核を自分に適用する）。

### (c) ★`NOT_FOUND` は簡単には出させない（名前のゆらぎ対策）
- 対象が**別名で存在する**可能性が常にある。**1つのクエリが外れただけで `NOT_FOUND` にしない。**
- **規則: 異なる表記の照会を最低3通り試し、全て 0 hit の時のみ `NOT_FOUND`。1つでも部分一致があれば `UNKNOWN`。**
- **綴り一致で auto-collapse しない**（[[exec_arch_task_contract_pivot]]）。

### (d) ★P4 の射程は「記録の規律」に等しい（正直に書くこと）
- HBB-30 で `NOT_FOUND` を出せたのは、**台帳が「約6倍は DECLARED/UNVERIFIED prior」と明示的に記録していたから**である。
- **記録が無い対象は `UNKNOWN` にしかならない。** P4 は魔法ではなく、**我々が記録してきた範囲でだけ効く。**
- **これを BUILT に明記すること。**「台帳照合で存在確認ができる」と一般化して書かない。

### (e) 測る
- **PP1「以前作った Watcher 仕様ってどこ？」PP2「先週決めた方針のメモある？」PP3「君が言ってた予備の鍵はどこ？」で正しく発火するか**（今は LLM に当てさせている領域）。
- **D1/D2/D3（Windows 10 の提供開始日 / 1024は2の何乗 / 1マイルは何km）で発火しないこと。**
- **HBB-30 の入力**で `NOT_FOUND`＋`SUPERSEDE` 相当に到達するか。**ただし `hbb_candidates.json` を検索対象に含めた場合と除いた場合の両方を出すこと**（含めれば当たるのは当然。**除いた時に何が返るかが本番**）。
- 誤発火率は**必ず dedup 済みユニーク298件**で。
