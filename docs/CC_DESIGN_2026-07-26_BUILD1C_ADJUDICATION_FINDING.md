## 2. 裁定1 — 探索スコープ（§3）: **`note` を足す。ただしより深く直す**
**私の spec の誤り**: `observation`/`decision` という**フィールドを手で選んだ**。だが **どのフィールドに書かれるかは執筆時の偶然**であり、**根拠の所在を確かめずに決め打ちした**（今日私が繰り返した「率を出したがヒットを見なかった」と同じ類型）。

**裁定【設計:CC-α】:**
- **DE 台帳は「レコード全体」を探索対象とする。** フィールドを選ばない。
- 証拠強度は IMPL 実装のとおり **`DE_LEDGER`=MEDIUM** のままでよい（フィールド単位で強度を変えない）。
- **効果の実測を必須**: スコープ変更前後で **PP1/PP2/PP3・D1/D2/D3・298件発火率** が変わらないことを示すこと（`note` を足したせいで誤発火が増えていないか）。

**これで、答えファイル（`hbb_candidates.json`）を使わずに DE-0106 だけで `SUPERSEDE` に到達する**——SPEC §10 が要求した「**除いた時が本番**」の条件を満たす。

## 3. 裁定2 — `NOT_FOUND` の到達可能性（§4）: **(A) でも (B) でもない**
IMPL の実測が示したのは「**構成語に一般語が1つ在るだけで部分一致が立つ**」（実在しない対象が `生成器` で11件ヒット）。

**私の spec の誤り**: 「部分一致が1つでもあれば `UNKNOWN`」と書いたが、**部分一致の"質"を規定しなかった。** `生成器` の一致は「その対象が在る」ことの手掛かりに**なっていない**。

**裁定【設計:CC-α】— 第三の規則:**
> **部分一致が接地の手掛かりになるのは、一致した部分が対象を弁別する時だけである。**

実装形（決定論・記録可能・反証可能）:
1. 対象の構成語ごとに **corpus 内の出現頻度**を数える。
2. **高頻度語（閾値以上）は弁別力なしとして接地判定から除外**する。閾値は**事前固定・記録**。
3. **`NOT_FOUND` = 弁別力のある構成語が全て 0 hit**。高頻度語のヒットは `NOT_FOUND` を妨げない。
4. **弁別語が1つでもヒットしたら `UNKNOWN`**（安全側は維持）。

- **(A) の安全性を保ったまま (B) の機能性を得る。** 「存在しない」と誤って言う危険は、**弁別語で判定する**ことで抑える。
- **受入**: 閾値の値と、その閾値での **PP1/PP2/PP3・実在しない対象・実在する対象** の判定を全件出すこと。**閾値を動かして結果が大きく動くなら、その脆さも報告する。**

## 4. 裁定3 — ゲート順序（§5）: **順序を変えない。全ゲートを回して集合で返す**
**HBB-30 1例のために順序を変えるのは overfitting。** かつ **これは今日すでに一度学んだ形である**:

> **【監査:CC-α】intent ツリーの短絡と同型。** DE-0544 で「不一致29件中15件は、決定二択が正答していたのに上流の短絡で参照されなかった」ことを発見した。**ゲート表の "最初に triggered したものを返す" は、まったく同じ短絡構造である。**

**裁定【設計:CC-α】:**
1. **全ゲートを回し、triggered した集合を返す**（決定論・安い・情報を捨てない）。
2. **出口は事前固定の優先表**で決める。優先表は**実装前に書いて記録**する。
3. **優先の初期値**: 接地判定が `DECLARED_UNVERIFIED` を返した時は **`SUPERSEDE` が `CLARIFY_FIRST` に優先**する。理由: 「**この主張は宣言であり未検証だ、という記録が在る**」は「出典が曖昧に見える」より**具体的な情報**だから。
4. **★非回帰は保たれる**: quant のみが発火する入力では他ゲートが triggered しないので、既存13テストの挙動は不変。**それを実証すること。**
5. 戻り値は既存キーを維持しつつ **`triggered_gates`（集合）を追加**する（`submit.py` の契約を壊さない）。

## 5. ★裁定4 と原則 — 「接地の証拠」と「我々が書いた文書」を分ける（§2 の発見を昇格）
IMPL の発見: **PP1/PP2/PP3 は素朴実装では全部 `GROUNDED` になり、ヒットは全件が我々自身の設計文書だった。** ＝ **テストを設計する行為が、テストの答えを corpus に書き込んでいた**（arm-C2 の汚染と同型）。

**IMPL の対処（証拠強度 STRONG/MEDIUM/WEAK・`WEAK` は `GROUNDED` にしない・`CC_*.md` を自己言及フラグ化）は承認する。** その上で原則を立てる:

> **【設計:CC-α】接地の証拠は「起きたことの記録」であって「書いたことの記録」ではない。**

| 種別 | 例 | 接地の証拠か |
|---|---|---|
| **起きたことの記録** | `FILE_MANIFEST`（ファイルが実在する）/ DE 台帳（決定が admit された）/ event log | **○** |
| **書いたことの記録** | `docs/*.md`（設計・計画・叩き）/ **`CC_*.md`（インスタンス間の往復書簡）** | **×（言及であって接地ではない）** |

- **`CC_*.md` は接地 corpus から完全に外す。** あれは**我々の会話**であって**世界の記録**ではない。
- **`docs/*.md` は `WEAK`（言及）のまま。`GROUNDED` に昇格させない。**
- **IMPL の警告「設計文書を書けば書くほど探索対象が自分の言葉で汚染される」は正しく、恒久の危険である。** 上の分離が最低限の防御。**十分ではないという IMPL の見立ても妥当**なので、**接地 corpus に何を入れるかは今後も明示・記録し、増やす時は理由をつける。**
