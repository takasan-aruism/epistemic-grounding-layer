## 1. 各原因の根拠（★現物を見た）

### 1.1 抽出器の偽陽性 21件 ―― 封印試験の本文に出る例示

```
a.py (x11)   <<<2DER:IMMUTABLE_TESTS>>> from impl import record_only_patch …
old.py (x3)  <<<2DER:IMMUTABLE_TESTS>>> from impl import add_locator …
rri/x.py(x4) <<<2DER:IMMUTABLE_TESTS>>> …
```

**`a.py` `x.py` `old.py` `tool.py` は、封印試験のコードが引数として渡している例示の文字列**であり、
**依頼文が指した参照ではない**。抽出器はマーカーの中を素通しで拾っている。

### 1.2 生成物 8件 ―― `impl.py` / `test_impl.py`

`build_planner` の prompt が **`target_file` は `impl.py`、`test_file` は `test_impl.py`** と命じている。
∴ **依頼の時点で存在しないのが正常**。「消えた参照」ではない。

### 1.3 ★repo境界 2件 ―― `rri/intent_record.py`

```
実体      : /home/takasan/rri/rri/intent_record.py   （★在る）
解決の試行: /home/takasan/rri/intent_record.py       （★無い）
```

**repo `rri` の中では `rri/intent_record.py` が正しい path** だが、
`_resolve_file` は `/home/takasan/` + 値 で見るため **repo 名の二重（`rri/rri/`）を吸収できない**。
∴ **実在するのに False**。★これが唯一の「直せる」解決器の欠陥。

### 1.4 命名の雛形 2件 ―― `twoder/X.py`

```
「置き先は 生成された source の "def X(" の X から 決まり twoder/X.py になる。」
```

**`X` は変数**であり file 名ではない。

### 1.5 予定ファイル 1件

```
「純関数 1本を新規 file `twoder/turn_overtaken.py` に作る。」
```

**本文が「作る」と明言**している。非実在で正常。

## 2. ★「本当に消えた参照」は 0件

git の歴史（`--diff-filter=ADR`）でも、同名探索（`find -maxdepth 4`）でも、
**旧パス・rename・move・削除の跡は1件も出なかった**。

∴ **34件は「参照が壊れている」のではなく、
①抽出器がマーカーの中を拾いすぎている（23件）
②これから作るものを見ている（9件）
③解決器が repo 名の二重を吸収できない（2件）**である。

---

## 3. ★refs を減らしていない

裁定の逐語「目的は refs を減らすことではなく」に従い、**台帳の refs を1件も消していない**。
本記録は**原因の確定だけ**である。

**直せる候補（★まだ直していない）**:

| # | 直せるもの | 効き |
|---|---|---|
| 1 | 契約マーカー（`<<<2DER:…>>>`）の中から file/symbol を拾わない | file 21件 ／ **symbol 727件**（既に入力から除外済み） |
| 2 | `_resolve_file` が repo 名の二重（`rri/rri/`）を吸収する | file 2件 |
| 3 | `impl.py` / `test_impl.py` を「生成物」として印を付ける | file 8件（★消さずに区別する） |

**★1 は symbol の 98.9% と同じ原因**（マーカー内を素通しで拾う）であり、
**file と symbol の両方に同時に効く**。
