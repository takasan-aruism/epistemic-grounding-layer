# D-3 — `_rel_prompt` の他の前提の洗い出し

## 3-1【設計:CC-α】結論: **`context` 以外に、硬い前提は見つからなかった**
7戦略それぞれについて「**LLM を呼ばずに機械で成立/不成立を判定できる前提**」を探した結果:

| 戦略 | 硬い前提 | 根拠 |
|---|---|---|
| `CONTEXT_RESOLVE` | **`context` が非空** | 定義が「**直前の文脈に**支配的な解釈があり」＝文脈が無ければ定義上あり得ない |
| `DIRECT` / `CHOICE` / `BOUNDED_MULTI_VIEW` / `INTENT_PROBE` / `PREMISE_PROBE` / `DEFER` | **前提なし** | 下記 3-2 |

**「見つからなかった」とそのまま書く**（無理に作らない・BUILD SPEC §5 の指示どおり）。

## 3-2【設計:CC-α】★作れそうに見えて作ってはいけないもの（記録して封じる）
既に機械で計算できる構造的事実が2つあるが、**前提にしてはいけない。**

| 使えそうな信号 | どこにあるか | **なぜ前提にしないか** |
|---|---|---|
| 指示語の束縛先の有無 | Build 1a の `BIND-RULE-001` | **束縛先が在っても `INTENT_PROBE` が正しい場合がある**（束縛先が複数ある等）。前提にすると**正しい選択肢を殺す** |
| 対象の接地状態（`GROUNDED`/`NOT_FOUND`/`UNKNOWN`） | Build 1c の `existence_grounding` | **接地していても `PREMISE_PROBE` が正しい場合がある**（存在はするが別物かもしれない）。同上 |

**規律**: **前提とは「不成立なら定義上あり得ない」ものに限る。** 「たぶん違う」は前提ではない。**これらは候補を削るのではなく、選択の材料として渡すなら別途設計する**（今は作らない・§0 の「精度が動くまで新しい機構を作らない」に従う）。
