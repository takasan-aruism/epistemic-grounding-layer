# 2DER 次段階の方向性と常時起動 Manager 最小構成 v0.1
経路表試金石で露出した欠落を、実装主体移管へつなぐための整理

## 0. 結論

現在の最優先は、「Claude の代わりに考える Manager」ではなく、「既存の2DERを自動で前へ進める最小 Manager」を置くこと。

2DERは、PLAN・Worker・Front Door・run_until_barrier・台帳など、実行に必要な主要部品を既に持つ。

今回止まった主因は、Workerの能力不足ではなく「READYな案件を誰かが叩かないと進まない」ことである。

したがって、まず駆動主体を内部化し、その後にRUNGATE判定・経路表の門条件・機能表へ進む。

設計自動化とUIは、経路表・機能表・運行状態が揃った後に着手する。

### 1.2 修正順序

① 常時起動 Manager v0 — READYな案件を検出し、既存の実行口を叩き、barrierまで進める。判断は最小限。

② runnable / RUNGATE整理 — 何を見て進行可否を決めるのか、古いBLOCKEDが新規案件を阻害するか、単一の_LAST依存が妥当かを確定する。

⑤ 機能表 — 機能→Capability→経路→実績→失敗・ノウハウを結ぶ。

⑥ 設計自動化 — 既存構造を壊さない設計、既存ノウハウ選択、経路整合性確認から始める。新構造の創発設計は後段。

⑦ UI — 人体図鑑＋機能表＋現在状態＋停止理由を人間が判断できる画面にする。

・経路表が未完成のままUIを先に作る。
・試金石で出た複数の問題を並列に広げて直す。

## 2. 常時起動 Manager の方向性

### 2.1 Manager v0 の目的

目的は「人やClaudeが手で次の口を叩く仕事を、2DER内部へ移す」ことだけ。

Manager v0 は知的な上司ではなく、台帳を見て既存の運行規則どおりにシステムを進める駆動装置とする。

### 2.2 最小責務

・台帳／task状態の変化を監視する。
・既存規則で runnable と判定された案件を検出する。
・既存の run_until_barrier 等の正式な実行口を呼ぶ。
・barrier、BLOCKED、完了のいずれかまで進める。
・どの案件を、誰が、いつ起動し、どこで止まったかを台帳へ残す。
・進められる案件がなければ休止する。

### 2.3 Manager v0 が判断しないもの

・設計の良し悪し
・コードの内容
・複数案件の戦略的優先順位
・権限境界の変更
・不可逆な変更の承認
・未知の例外に対する創作的対処

### 2.4 状態遷移イメージ

```
台帳に新状態
  ↓
Managerが検知
  ↓
runnableかを既存規則で確認
  ├─ No → 理由を記録して休止
  └─ Yes → 正式な実行口を呼ぶ
             ↓
        barrierまで進行
             ↓
     結果・停止理由を記録
             ↓
            休止
```

### 2.5 必須計器

### 2.6 受入条件（v0）

・同じ試金石を再実行し、Claudeが書いた実装行数 = 0。
・MGR／Takaが run 系の口を手で叩いた回数 = 0。
・READY状態からManager自身が実装工程へ進める。
・停止した場合、停止工程と理由が台帳から一意に引ける。
・Managerが勝手に設計・コード修正を行わない。
・既存の正式な実行口を使用し、裏口を新設しない。
・既定経路の通常応答・既存非回帰を壊さない。

## 3. Manager v1 以降（保留）

v0が成立してから、以下を段階的に追加する。v0と同時に入れない。

・複数 runnable 案件の優先順位付け
・期限・重要度・依存関係による選択
・BLOCKED案件の再評価・再起動
・経路表Workerとの連携による配線異常検出
・失敗ノウハウの強制参照と成績利用
・将来的なGenesis Attention Centerとの統合

## 4. 今回の試金石から固定する原則

**能力不足と運行不足を分ける** — Workerが書けないのか、そもそもWorkerまで届いていないのかを混同しない。

**『無い』の前に一覧を引く** — 口・部品・経路・既存機能を名前の推測で判断しない。

**経路表を先に見る** — 経路に在るものを『無い』と報告しない。

**存在だけでなく条件を見る** — 門が在るだけでは診断できない。何を見て開閉するかを経路に結びつける。

**止まりは失敗ではない** — 契約が不足して止まったなら、不足名を次の契約改善材料として残す。

**自動化は人の行為を置換した事実で測る** — 『自動化したつもり』ではなく、人／Claudeの介入回数を0へ近づける。
