# 【設計・Taka 案】★戻すのではなく ★分岐する（新 ID を立てる）／ ★終わり方を2種に分ける

宛: MGR ／ 発: DESIGN（監視兼務）／ 2026-08-10 07:47 ／ TYPE=設計（★Taka 案が主・★私の追加は §4）

## 1. ★Taka 逐語（歪めない・要約しない）

> **台帳の分岐**
> **台帳1の工程管理の途中で問題が発生した場合は、異なる ID を立てる。異なる ID の台帳が紐づいている必要性がある。前台帳の進行は、新しい ID の完成を条件とする。これで実質戻る、がなくなる。事実戻るわけじゃない。なんらかの修正が走った、が正しい。**
> **例えば特定 ID が進行中不要になった場合なども、そこに関連するシステムやファイルをどう扱うか？ という問題は残る。作りっぱなし問題を考えれば重要なテーマである。本来 ID は、終わったと簡潔に完了させられるケースと、それができないケースがある（後始末どーすんねん）ので、そこを分ける仕様にもなるしいいんじゃないかな。設計センスの良い案があればそこに加えるか、そもそもこっちの方がいい、で進めればよい**

## 4. ★私の追加（★2点・★Taka 案に足す形）

```
★★① ★終わり方の2分を ★機械が判定する（★人に決めさせない）
   ★きれいに閉じられる : ★★その ID が作った物が ★全部 使われている
   ★★後始末が要る     : ★★呼び手0 の物 / 配置されていない物 が 残っている
   → ★閉じる操作の時に ★★「後始末が要る」と ★機械が言う
   → ★★作りっぱなしが「閉じる瞬間」に 名指しで出る
   ★材料: ★affected_artifact_ids ＋ ★artifact_registry ＋ ★呼び手の有無

★★② ★「親は子の完成を待つ」を ★無条件にしない
   ★★子が DROPPED / DEFERRED になった時、★親がどうなるかを ★先に決める
   → ★決めないと ★★親が永久に止まる
   ★★実績（本日 実測）: ★手番が 10時間 停止 ／ ★4件が 1か月 停止（★誰も気づいていなかった）
   ★候補: ★子が畳まれたら ★親も自動で「待ち」から外れ、★★理由が親に残る
```

## 5. ★受入（★案）

```
★① ★問題が起きた工程から ★新 ID が1件 立ち、★親から ★子が引けること（★1件で可）
★② ★★親の進行が ★子の完成を条件にしていること（★front door から読める）
★③ ★★子を畳んだ時に ★親が止まったままにならないこと（★実測で示す）
★④ ★★ID を閉じる時に ★「後始末が要る/要らない」が ★機械の判定として出ること
★⑤ ★「要る」と出た ID について ★残っている物が ★名指しで並ぶこと（★0件なら0件と書く）
★⑥ ★人が判定を上書きした回数を併記（★0 が目標）
```
