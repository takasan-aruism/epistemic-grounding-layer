## 1. 埋めた1点

RRI 逐語:「★『seed が効かない』の **原因**（サーバ側か 呼び方か）は **切り分けていない**」。

**2DER のコードを通さず** `:8005` を直接叩いた（body は `intent_strategy._llm` と同一形・temperature=0・seed=0・
`enable_thinking:false`）。1条件 n=8。

| 条件 | prompt 長 | byte が異なる本数 | 決定 |
|---|---|---|---|
| 短い・答えが1つに決まる問い(mt=8) | 22字 | **1 / 8** | ― |
| 短い・答えが1つに決まる問い(mt=256) | 22字 | **1 / 8** | ― |
| 長い・答えが1つに決まる問い(逐次) | 465字 | **2 / 8** | ― |
| 長い・答えが1つに決まる問い(同時8) | 465字 | **2 / 8** | ― |
| **本番の問い(逐次)** | 901字 | **7 / 8** | DIRECT 7 / BOUNDED_MULTI_VIEW 1 |
| **本番の問い(同時8)** | 901字 | **8 / 8** | DIRECT 5 / DEFER 2 / 語なし 1 |

### 読み取れること

1. **サーバは素で非決定ではない。** 短く答えが1つに決まる問いは **8/8 バイト一致**。
   `max_tokens` を 8 → 256 にしても一致（★max_tokens は原因ではない）。
2. **長い prompt では、答えを1つに固定しても byte が 2種に割れる。**
   ∴ **`seed` はバイト決定論を保証していない**（残差はサーバ側に在る）。ただし **2/8 であって 7/8 ではない**。
3. **判断が割れる主因は問いの側。** 同じ長さ帯で、答えを固定した対照は 2種、
   本番の多義的な問いは **7〜8種＋決定そのものが 3種**へ散る。
   ∴ K4/K5（問いの欠陥）と **矛盾しない**。Inference Control が独立に支持した。
4. **同時実行は決定の散り方を悪くする**（逐次 DIRECT 7/1 → 同時 DIRECT 5 / DEFER 2 / 語なし 1）。
   ★これは n=8 の1回ぶん ∴ **OBSERVED 止まり**（REPRODUCED にしない）。

## 3. 再利用できる形（条件 → 操作 → 結果）

- **条件**: LLM の出力を門の引き金にする呼出点で、`system_prompt=ABSENT` かつ `schema_enforced=ABSENT`。
- **操作**: `seed` を足す／引く回数を増やす。
- **結果**: **効かない**。1引きの p が中間なら合議は期待値を動かさない（K3）。
  先に効くのは **問いを直すこと**（K5: 整合を文にする）。
- **∴ 実装上の含意**: 「揺れる → seed を固定 → 3引きで多数決」は、この条件下では **費用だけ 3倍**になる。
