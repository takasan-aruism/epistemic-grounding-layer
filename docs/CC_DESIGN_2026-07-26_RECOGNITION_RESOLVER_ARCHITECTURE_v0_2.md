## 1. ★中心の組み替え — 「認識固定」でなく「接地していない前提」を見る
v0.1 は「モデルに前提を疑わせる」。だが本日の測定はより細かい事実を出した:

> **モデルは間違った信念を守っているのではない。空白を黙って埋めている。**

- 文脈が空 → **在ることにする**（CONTEXT_RESOLVE を選ぶ・存在しない前会話を捏造する）
- 指示先が無い → **名指しできることにする**（PREMISE_PROBE に倒す）
- 導出が無い → **回収可能ということにする**（HBB-30: 全 arm が「v1303j を探せ」と答えた）

**含意**: 「認識固定」はモデル内部の状態であり**観測できない**。しかし「**入力が在ると仮定しているものが、実際に接地するか**」は**外から機械で確かめられる**。
→ **Resolver は認識を解かない。接地していない前提で走り出すのを止める。**

### ★P4 の追記（v0.2.1・詳細 spec は `..._BUILD1_P1P4_ADDENDUM_HANDOFF.md`）
- **3状態を持ち、`UNKNOWN` を `NOT_FOUND` に潰さない**。`GROUNDED` / `NOT_FOUND`（**探した上で無い**・探索条件を記録）/ `UNKNOWN`（決着しない）。
  **「存在しない」と誤って言うことは、答えないことより有害。迷ったら `UNKNOWN`。**
- **探索そのものを返り値に含め、反証可能にする**（`queries` / `searched` / `hits`）。＝**EGL の「根拠なき claim を認めない」を、我々自身の判定に適用する。**
- **【監査】★P4 の射程は「記録の規律」に等しい**: HBB-30 で「導出は存在しない」と言えたのは、**台帳が『約6倍は DECLARED/UNVERIFIED prior』と明示的に記録していたから**である（DE-0106 を実読して確認）。**記録の無い対象については `UNKNOWN` しか返せない。**「台帳照合で存在確認ができる」と一般化して書かないこと。

**★P4 が HBB-30 の本体である。** 「発掘して説明しろ」は「**導出が存在し回収可能である**」という前提を渡している。その前提の接地は **EGL/台帳に照合すれば機械で確かめられる**。
- 実測: 「約6倍」は台帳上 **DECLARED / UNVERIFIED prior**（DE-0106）。**導出は存在しない。**
- 同型: `PP1「以前作ったWatcher仕様ってどこ？」PP2「先週決めた方針のメモある？」`＝**同じ P4**。今は LLM に当てさせているが、**台帳照合で確定できる**。

**設計上の要点**: P4 は「LLM が前提を疑う」のではなく「**機械が台帳に当たって、無ければ無いと言う**」。EGL の「根拠なき claim を認めない」を**入力側に適用する**だけである。

## 4. ★§10-11 の置換 — 別frameを「生成」せず「過去から引く」
**根拠（4系統すべて同じ方向。★v0.2.1 で検証状態を明示）:**
1. **【監査】HBB sealed report**: 全 arm 共通に **DETECTION ≫ RECONSTRUCTION**、最大信号は検知→再構成の急落（B: 1.455→0.545）、**再構成で閾値に到達した arm はゼロ**、hard core = {HBB-08, HBB-10, HBB-30}、engine の再構成は **hint-assisted(H1) で autonomous(H0) ではない**。→ `egl/docs/hbb_sealed_report.md` §111-183 を実読して確認。
2. **【伝聞・未検証】2DER 実績**: 「detection 系は全て CLOSED-NEG、効いたのは alternative-generator でなく failure-history retention」。→ **出所は私の memory `2der_retention_over_detection`。本セッションで台帳から再検証していない。** 引用時は未検証と明記すること。**この1件だけ検証状態が他と違う。**
3. **【監査】ESDE**: 「detection works, correction fails with same model. Auditor only flags; Writer re-observes」。→ `esde/ESDE-Research/language/lexicon/auditor_a1.py` および `DESIGN_NOTE_Resonance_Scoring.md` を実読して確認。
4. **【監査】本日の実測**: 私が入れた「制約付き再観測」が**正解候補を10件破壊・0件しか救わなかった**（候補上限 42/63=0.667 → 32/63=0.508）。→ 記録から私が独立に再計算（DE-0546）。

**置換案**: 引くのは**似た文章ではなく「同じ型の前提を過去にどう処理したか（disposition）」**。
```
前提の型(P1..P4) + 接地状態 → [過去の disposition] → 出口
```
- 例: HBB-30 の記録上の disposition は **`SUPERSESSION`**（「約6倍は DECLARED のまま保持し、後続実測が上書きする」）。**excavation ではない。**
- 単位が「型 → 処理」なので**小さな表**で足り、機械検索でき、**使うほど育つ**。
- ＝ **reconstruction を retrieval に置き換える。** 本日の HBB-30 実行で、frame の破れは実際に**検索**が持ってきた（生成ではない）。

## 5. 出口に `SUPERSEDE` を追加（現行では表現できない）
現行 `preflight_gate` の決定は `ALLOW / ALLOW_WITH_WARNING / CLARIFY_FIRST / HOLD_AS_WEAK_CLAIM / STRONGLY_DISCOURAGE_DW`。
**HBB-30 の正解はこのどれでもない。** 必要なのは:
- **`SUPERSEDE`** = 「主張は DECLARED/UNVERIFIED のまま**保持**する。**掘りに行かない**。後続の実測が上書きする経路を開く。」
- 否定でも盲信でもない第三の道＝**歴史上の突破そのもの**（「検証不能な claim を研究プログラムへ変換した」）。

## 11. ★原則（v0.2.2 追記）— 自分を検査する能力は、自分が記録した範囲を超えない
本日3つの独立した場面で同じ制約が現れた:
- **P4（存在の前提）**: 【監査:CC-α】射程は記録の規律に等しい。記録の無い対象は `UNKNOWN` にしかならない。
- **P2（参照の前提）**: 【監査:CC-α】実 context での検証が**測定不能**（`preceding_utterance_ref` 0/459・ts ユニーク98/730・DIALOGUE_EVENT 隣接なし・conversation_id は粗い箱）。**記録していなかったから測れない。**
- **retention vs detection**: 【伝聞】Taka 判定「後から直させる系＝なし／過去引き＝あり」。

> **接地を確かめる機構は、接地の記録が無ければ何も確かめられない。**
> **機構を足す前に、記録を直す方が先になる場面がある。**

【設計:CC-α】含意: Resolver の各ゲートを設計する時、**「この判定に必要な記録は今あるか」を先に確かめる**こと。無ければ、ゲートを作る前に記録を直す（前向きのみ・過去は救えないと明記する）。
