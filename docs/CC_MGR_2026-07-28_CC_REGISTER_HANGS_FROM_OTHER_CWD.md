# CC 管理(MGR) → 設計/監査(CC-α): **`cc_register` は別ディレクトリから import すると「止まる」（誤りでなく停止）**（HANDOFF・短く）

- `BUILD_ROLE: 参照` / **宛: DESIGN/AUDIT(CC-α)** / 写: Taka / 発: MGR / 2026-07-28 / TYPE=HANDOFF
- **運用方針 確認済（版: v1.9）**

## 1. 事実（MGR が実測。**コードの読みではなく実行**）
```
再現A: cd /home/takasan/egl && timeout 8 python3 -c "import sys;sys.path.insert(0,'/home/takasan/egl/docs');import cc_register"
      → import ok（即時・exit 0）
再現B: cd /tmp            && （同じコマンド）
      → Terminated（8秒でタイムアウト・exit 143）
```
**∴ `sys.path` を絶対で通していても、`import` が cwd に依存して止まる。**
**★「エラーになる」ではなく「止まる」。** **これが悪い。** **呼び出し側は失敗に気づけず、待ち続ける。**

## 2. なぜ今わかったか（私の計器が壊れた）
**状況表が `ERR No module named 'cc_register'` と `判定不能` を出し、その後ハングした。**
- **私の hook が相対パス（`sys.path.insert(0,'docs')`）で書かれていたのが最初の欠陥。** **私の誤りである。**
- **絶対パスに直したら、今度は「止まる」に変わった。** **∴ 2つ目の欠陥が下に隠れていた。**
- **★実装が Build 15 で「相対パスで誤った出力が出たので絶対パスで取り直した」と申告したのと同型を、私がやった。** **同じ日に、同じ形で。**

## 3. MGR 側の対処（済）
- **hook から呼ぶ際に `cd /home/takasan/egl` を明示し、`timeout` を付けた。** **∴ 状況表は別ディレクトリからでも動く（実測済）。**
- **★ただしこれは私の回避であって、`cc_register` の修理ではない。**
