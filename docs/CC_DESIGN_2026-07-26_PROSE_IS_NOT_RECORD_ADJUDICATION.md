## 3. ★裁定の訂正 — 「存在の接地」と「地位の宣言」は別の問い
HBB-30 が要求するのは **2つの異なる問い**であり、**同じ corpus で両方を answerable にしようとしたのが誤りだった。**

| 問い | 何を知りたいか | 許す証拠 |
|---|---|---|
| **存在の接地** | 「その X は在るのか」 | **起きたことの構造記録のみ**: `FILE_MANIFEST`（ファイルが実在する）/ `egl_admission`（DE が admit された事実）/ event log。**散文は一切使わない** |
| **地位の宣言** | 「その主張はどういう地位か（宣言/実測/上書き済）」 | **我々が意図的に登録した構造データのみ**。**散文を grep しない** |

### (a) 存在の接地: 散文を corpus から外す（§2 撤回）
- **DE 台帳の散文（`observation`/`decision`/`note`）を接地 corpus から除外する。**
- 使うのは **`design_evidence_id` / `egl_admission` の admit 事実 / `evidence_refs` が指すファイル実体**（＝起きたこと）。
- `docs/*.md` は既に `WEAK`。**`CC_*.md` は除外済**（前回裁定）。**散文の口を全部塞ぐ。**

### (b) 地位の宣言: `CLAIM_STATUS` 台帳を新設する【設計:CC-α】
DE-0106 の `note` を**実行時に grep する**のではなく、**一度だけ人手で登記する。**
```
{claim_id, claim_text, status: DECLARED_UNVERIFIED | MEASURED | SUPERSEDED,
 source_de, superseded_by, authored_by, ts}
```
- HBB-30 の「約6倍」＝ `status=DECLARED_UNVERIFIED` / `source_de=DE-0106` の**1エントリ**。
- **汚染が構造的に不可能**: 台帳には「誰かが意図して登記したもの」しか入らない。我々が報告文にどんな語を書いても増えない。
- **正直**: システムが知るのは「**我々が登記したこと**」であって「**たまたま書いたこと**」ではない。
