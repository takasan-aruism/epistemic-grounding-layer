### 1.1 見つけた欠陥2つ（どちらも実測）

**① `_BULLET` が記号の直後に空白を要求していた**

```
_BULLET = r"^\s*(?:[-*・]\s|\d+[).]\s?)"
「・1つ目: 停止中の走行を一覧にする」 -> 箇条書きと 認識されない
```
∴ 2つの言明が1件になっていた。空白を任意にした。
**★`--check` や `-abc` と紛れないよう英数字が続く形は除いた**（実測で確認）。

**② 見出しの形がもう1つあった** ―― `【…】` だけの行。既存の `…:` と同じ扱いにした。

### 1.2 ★★version/supersede が壊れていた（Taka が名指しした確認項目）

少数実走で**すぐ出た**:

```
行 2 -> 3 に割り直したのに ★list_typed は 5行 を返した
```

原因: `typed_id` は `(thread, segment_index, source_text)` から決まる ∴
**割り方が変わると id も変わり、古い版の行が残る**。`list_typed` は id で重複を潰すだけなので
**新旧が混ざって返っていた**。

**直した**: `record_typed` は常に**その依頼の完全な集合を1つの `ts` で**書く
（本番の呼び手は `detail_backfill` の1つだけで `structure()` の返りをそのまま渡す）
∴ **最後に書かれた `ts` の分が「いまの版」**である。

- `list_typed(thread_id)` … いまの版だけ
- `list_typed(thread_id, all_versions=True)` … 過去も引ける（**台帳は append-only ∴ 消していない**）

封印試験2本で固定した。**私の期待値が一度誤っていたので実測に合わせて直した**
（「う。」は位置も原文も変われば別 id になるため、全履歴は 4 ではなく 5）。

### 1.3 少数実走で確かめたこと

```
★原文保持    : 新しい行の source_text が すべて原文に逐語で在る（原文に無い行 0）
★source_span : 新 全行が (start, end) を持つ
★provenance  : parent_request_id が 新 全行で task と一致
★refs        : 旧0 -> 新0（該当行に参照が無い＝失われていない）
★actor       : 既存の recorded_by/recorded_via は そのまま

★既存 kind   : ED65242E / EF6826DC の分布は baseline と完全に同じ
```
