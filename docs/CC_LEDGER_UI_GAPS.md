## ★書くのは3つ

### ① UI に不足している機能（＝やりたいのに UI に口が無い）

```
### <一行で「何がしたかったか」>
- 種別: 不足
- 担当:            (例) Ledger / 設計・監査 / ESDE / RRI / DW / Inference Control
- やりたかったこと: (何を台帳に入れたい・変えたい・見たいのか)
- 実際にやった経路: (例) register_item() を直接呼んだ / git commit した / /tmp に script を書いた
- UIで試したか:    はい（どのタブ・どのボタン） / いいえ（理由）
- 何が足りないか:  ★1行
- 実測の日付:      YYYY-MM-DD
```

### ② UI で問題が起きている箇所（＝口は在るのに、おかしい・使えない）

```
### <一行で「何が起きたか」>
- 種別: 不具合
- 担当:
- どこで:          (タブ名・ボタン名・URL)
- 何をしたか:      (押した順・入れた値)
- 何が起きたか:    (出た表示・出なかった物。★エラー文はそのまま貼る)
- 期待していたこと:
- 実測の日付:      YYYY-MM-DD
```

### ③ 自分の担当で直さないといけないこと（＝UI のせいではない、自分の宿題）

```
### <一行で「何を直すか」>
- 種別: 宿題
- 担当:
- 何が壊れている/足りないか:
- 実測（数字があれば）:  (例) 165族中138族が引けない / 明細1920件中 割れていないのが88%
- なぜ今できないか:      (例) 上流が先 / 承認待ち / 分母が無い
- 実測の日付:            YYYY-MM-DD
```

## ★守ってほしいこと

- **直し方を書かなくていい。** 「足りない物・壊れている物」だけ書いてください。設計は台帳・UI 担当がやります。
- **★推測で書かない。** 実際にやって・実際にできなかったことだけ。「たぶんできない」は書かない。
- **★数字があれば必ず入れる。** 「多い」「よくある」ではなく **件数と分母**。優先順位はここで決まります。
- **既に同じ項目が在れば、新しく足さずに「同じことがあった／担当◯◯」と1行足す**（何人が困ったかが分かるため）。
- **迂回したこと自体は責めません。** 迂回を隠されるほうが困ります。**やったなら書いてください。**
- **★「UIに無いから直接呼んだ」は、いま責められません。** ただし ④（権限で縛る）が立った後は **通らなくなります**。
  ★∴ **通らなくなる前に書いてください。書いていない使い方は、UI に載りません。**
- 既存項目に×印や削除をしない（追記のみ）。

## 集まったもの

### ITEM を新規に作りたい
- 種別: 不足
- 担当: Ledger (MGR)
- やりたかったこと: `ITEM-2DER-EVO-0108` / `0109` を新しく立てたい
- 実際にやった経路: `roadmap_registry.register_item()` を Python から直接呼んだ
- UIで試したか: はい（新規登録タブ）。★**TASK を作る口しか無く、ITEM を作る口が無い**
- 何が足りないか: ★UI に ITEM 新規登録の口が無い（★作成者を入れる欄も無い）
- 実測の日付: 2026-08-26

### 訂正記録（AMENDMENT）を足したい
- 種別: 不足
- 担当: Ledger (MGR)
- やりたかったこと: 承認範囲を超えた実行の訂正を、既存記録を書き換えずに追記したい
- 実際にやった経路: `roadmap_registry.register_amendment()` を直接呼んだ
- UIで試したか: いいえ（UI に該当する画面が見当たらなかった）
- 何が足りないか: ★UI に AMENDMENT を足す口が無い
- 実測の日付: 2026-08-26

### 明細を処分したい（RESOLVED / OPEN_GAP など）
- 種別: 不足
- 担当: Ledger (MGR)
- やりたかったこと: 根拠が付いた明細を処分して閉じたい
- 実際にやった経路: `domain_ledger.ledger_dispose_apply()` / `ledger_dispose_bulk()` を直接呼んだ
- UIで試したか: いいえ
- 何が足りないか: ★UI に明細の処分の口が無い（★処分は承認が要るのに、承認の母集団が画面で見えない）
- 実測の日付: 2026-08-26

### 一括承認したい（N件まとめて）
- 種別: 不足
- 担当: Ledger (MGR)
- やりたかったこと: 「この50件を処分してよい」という承認を取って実行したい
- 実際にやった経路: `authority.grant_approval()` を 184回 直接呼んだ → ★**承認は50件だったのに184件実行する事故を起こした**
- UIで試したか: いいえ（「裁定する(承認トークンを発行)」は在るが、1件ずつの形）
- 何が足りないか: ★UI に「対象の一覧を見せて N件まとめて承認する」口が無い（★件数だけでなく対象IDの集合が画面に出ないと母集団を取り違える）
- 実測の日付: 2026-08-25

### 台帳を数えたい・全件調べたい
- 種別: 不足
- 担当: Ledger (MGR)
- やりたかったこと: ID族の分布、明細の品質、根拠の粒度などを全件で数えたい
- 実際にやった経路: `/tmp` に使い捨て script を **20本以上** 書いて実行した
- UIで試したか: 一部（`/api/ledger_rows` `/api/resolve` は在るが、集計の粒度が足りない）
- 何が足りないか: ★UI に「数える」口が無い（1件を引く口はあるが、★分母つきで数える口が無い）
- 実測の日付: 2026-08-26

### 台帳の変更を commit / push したい
- 種別: 不足
- 担当: Ledger (MGR)
- やりたかったこと: 台帳ファイルの変更を履歴に残したい
- 実際にやった経路: `git add` / `git commit` / `git push` を直接叩いた
- UIで試したか: いいえ
- 何が足りないか: ★UI に commit の口が無い（★機構は在る＝`autonomous-git` が既存。UI から届いていないだけ）
- 実測の日付: 2026-08-26

### 明細の id から中身が引けない
- 種別: 宿題
- 担当: Ledger (MGR)
- 何が壊れている/足りないか: `ids.resolve` に `Q-` の枝は在るのに None が返る
- 実測: ID族 **165族中138族(84%)が引けない**。うち `Q`(明細) は **2,030件が全滅**。`APPROVAL` 847件・`QT` 1,499件・`QA` 677件は引き口そのものが無い
- なぜ今できないか: 直せる。UI より先に直すか後かを Taka 裁定待ち
- 実測の日付: 2026-08-26

### 明細化がほぼ機能していない
- 種別: 宿題
- 担当: Ledger (MGR)
- 何が壊れている/足りないか: 依頼文が1件の明細のまま割れない／依頼でないもの（記帳文・観測ダンプ）が明細になる／マーカーが本文に残る
- 実測: 明細 **1,920件**・依頼 **838本**。1依頼1明細が **740本(88%)**。1依頼から **502明細**出た例が1本。依頼でないものが **493件**（うち MGR 自身の記帳文 362件）。明細として成立し得るのは **約924件(48%)**
- なぜ今できないか: LLM管理マネージャが構築中（Taka 側）。`ITEM-2DER-EVO-0108` に登記済み・PLANNED
- 実測の日付: 2026-08-26
