## ★書き方（これだけ守ってください）

**1件 = 1ブロック。下の6行を埋めるだけ。** 判断は要りません。**できなかった事実を書くだけ**です。

```
### <一行で「何がしたかったか」>
- 担当:            (例) Ledger / ESDE / RRI / DW / Inference Control
- やりたかったこと: (何を台帳に入れたい・変えたいのか)
- 実際にやった経路: (例) roadmap_registry.register_item() を直接呼んだ / git commit した / /tmp に script を書いた
- UIで試したか:    はい（どのタブ・どのボタン） / いいえ（理由）
- 何が足りないか:  ★1行。(例) ITEM を作る口が UI に無い / 作成者を入れる欄が無い
- 実測の日付:      YYYY-MM-DD
```

**★守ってほしいこと**

- **直し方を書かなくていい**。「足りない物」だけ書いてください。設計は台帳・UI 担当がやります。
- **★推測で書かない**。実際にやって・実際にできなかったことだけ。「たぶんできない」は書かない。
- **既に同じ項目が在れば、新しく足さずに「同じことがあった」と1行足す**（何人が困ったかが分かるため）。
- **迂回したこと自体は責めません。** 迂回を隠されるほうが困ります。**やったなら書いてください。**
- 既存項目に×印や削除をしない（追記のみ）。
- **★「UIに無いから直接呼んだ」は、いま責められません。** ただし ③（権限で縛る）が立った後は **通らなくなります**。
  ★∴ **通らなくなる前に、ここに書いておいてください。** 書いていない使い方は、UI に載りません。
