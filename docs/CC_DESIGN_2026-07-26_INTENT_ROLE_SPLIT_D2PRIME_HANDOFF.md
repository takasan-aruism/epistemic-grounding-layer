## 0. 前提（前回の帰属を取り違えないこと）
前回 arm-D の 0.4603 は**役割分割の実力ではない**。**私が handoff §3 で義務づけた「監査flag→制約付き再観測」が正解候補を10件落とし0件得た（純粋に破壊的）**ため、候補集合の上限が **0.667 → 0.508** に落ちた結果である。**＝DESIGN(私)の spec バグ。IMPL の実装は指示どおりで正しい。**
一方で清潔に測れた部分は良好: **選択役 29/32 = 0.906**、**順序一致 0.952**（arm-C3 の二択は 0.6481＝35%変動）。**役割分割の後半は機能している。**

## 1. ★最優先: 再観測を廃止した実測を取る（arm-D2p-A）
- **監査 flag による再観測を一切行わない。** 選別役の初回出力をそのまま候補集合とし、選択役へ渡す。
- 前回の初回上限 42/63 = 0.6667 に対し、**選択役効率 0.906 が保たれれば ≒0.60** の見込み（**推計。実測で確かめるのが本タスク**）。
- **これが役割分割の素の実力**であり、arm-C3(0.5397) との比較はこの数字で行う。

## 2. 膨張対策は「削れ」でなく「矛盾を機械で除く」（arm-D2p-B）
LLM に減らさせない（ESDE:「**検出は効くが、同一モデルによる修正は失敗する**」）。**決定論で候補を落とす。**
- `MUTEX` ペアが同時 YES の時、**事前固定の優先規則**で片方を機械除去する。規則は**先に書いて記録**し、実行時に変えない:
  1. `DEFER` は他と両立しない → 他に YES があれば **DEFER を落とす**（不正形なら他が YES にならないはず）。
  2. `DIRECT` と {`INTENT_PROBE`,`PREMISE_PROBE`} 同時 → **DIRECT を落とす**（確認が要るなら直接答えは成り立たない。安全側）。
  3. `DIRECT` と {`BOUNDED_MULTI_VIEW`,`CHOICE`} 同時 → **落とさず両方残す**（選択役に判断させる。前回 CR1 で正解 CONTEXT_RESOLVE が候補にあったのに BMV を選んだ例があり、ここは選択役の仕事）。
- **除去は必ず記録**（何を何の規則で落としたか）。**除去の前後の候補集合を両方残す**（隠さない）。
- 規則1/2 が正解候補を落としていないかを **--check で必ず集計**（`MUTEX_DROPPED_CORRECT` として件数を出す。**落としていたら正直に報告し、規則を見直す**）。

## 3. 選別役の相対比較版（arm-D2p-C・IMPL 提案を採用）
- 7戦略を**1呼出で全部見せ**、「**当てはまるものに YES。通常1〜2個、最大2個まで**」と**員数を構造で強制**（ESDE の「員数」を1呼出内で効かせる）。
- **独立判定版（A/B）も必ず残して比較する。** 独立性は短絡回避の根拠なので捨てない。**相対版が独立版を上回るかは未知＝measure-first。**
- 相対版は「勝者を選ぶな」が効きにくい（同一文脈に7つ並ぶため比較が起きる）。**この副作用が出るかも観測対象。**

## 4. ★指標は4つ必ず併記（前回、最終一致だけ見て誤帰属しかけた）
| 指標 | 意味 |
|---|---|
| (a) **最終一致**（seed平均） | arm-C 0.5833 / arm-C3 0.5397 と同一物差し |
| (b) **候補集合の上限** | 正解が候補に入っていた率＝**選別役の天井** |
| (c) **選択役効率** | (a)/(b)＝候補に正解がある時の的中率 |
| (d) **回答時精度** | NO_CANDIDATE を除いた精度（「答えない」を「間違い」と混ぜない） |

- (b) が低ければ選別役、(c) が低ければ選択役が犯人。**この分解なしに結論を書かないこと。**

## 5. NO_CANDIDATE の内訳調査（メニュー欠落の切り分け）
- 前回 NO_CANDIDATE=12。**fixture 別に内訳を出す。**
- 特に **CH1「どのデータベースを採用すべき？」型**は、モデルが「要件が不明だから聞き返したい」と判断しているのに **§9 の7戦略に「基準/要件を確認する」型が無い**ため全戦略 NO になっている可能性がある（DE-0544 §3 で起票済のメニュー欠落）。
- **メニューの穴による NO_CANDIDATE は model の失点に数えず、別枠 `MENU_GAP_SUSPECT` として報告する。**（判定は DESIGN propose → Taka 承認。**IMPL は分類しない・材料のみ**。）
