## 0. 設計の要点（3つ）
1. **★新しい ID 族を作らない。** 文書の id は **`ART-<sha1(repo|relative_path)>`**＝`artifact_registry.artifact_id_for()` と同じ計算。**∴ 退役時、id を付け替えずにそのまま登記へ移せる。**
2. **★列は MGR が挙げた8つだけ。** 足していない。**足していないことを §4 に明記する。**
3. **★退役条件を台帳の1行目に書く**（MGR §3）。**書けない台帳は作らない。**

---

## 1. 台帳
```
場所: egl/docs/CC_REGISTER.jsonl      （文書と同じ場所。追記のみ・latest-wins）
1行目（_meta として固定）:
  {"_meta": "CC 管理台帳(暫定)。目的=3インスタンスが『どの文書が在り、誰宛で、未処理か』を
             ディレクトリ走査でなく1本から知るため。★退役条件=front door から ART- の本文が
             返るようになったら、内容を artifact_registry の登記へ移し、本台帳を廃止する。
             id は ART-<sha1(repo|relative_path)> で登記と同一＝付け替え不要。"}
```

## 2. 行の形（2種類だけ）
```
① 登録行（文書を置いた者が、置くのと同じ作業で1行）
{"kind":"DOC", "doc_id":"ART-xxxxxxxx", "path":"egl/docs/CC_....md",
 "type":"HANDOFF|BUILD_SPEC|BUILT|FINDING|STATUS",
 "from":"MGR|DESIGN|IMPL", "to":"MGR|DESIGN|IMPL|TAKA",
 "build_role":"IMPL_SOURCE|REFERENCE|SUPERSEDED",
 "supersedes":"ART-yyyyyyyy|null", "ts":"<実時刻>"}

② 処理行（宛先が応答を置いたときに1行）
{"kind":"DONE", "doc_id":"ART-xxxxxxxx", "by":"MGR|DESIGN|IMPL",
 "by_doc_id":"ART-zzzzzzzz", "ts":"<実時刻>"}
```
**「未処理」= `DOC` 行が在り、対応する `DONE` 行が無いもの。** **状態を書き換えない**（追記のみ）。

## 3. 誰がいつ書くか
| | |
|---|---|
| **`DOC` 行** | **文書を置いた者が、置くのと同じ作業で書く。** 別作業にしない（別にすると必ず抜ける） |
| **`DONE` 行** | **宛先が、応答文書を置いたときに書く**（`by_doc_id` に自分の文書 id） |
| **読む側** | 各インスタンスの作業板と、MGR の状況表 |

**★これは「配置は Claude の役割。ただし記録が残る場合に限る」と同型である。** **新しい権限を作らない。**

---

## 4. ★足していないもの（延長しない・MGR §4）
**次はすべて「要る理由が思いついたが、入れなかった」ものである:**
- 所要時間 / 応答までの経過 / 件数の集計 / 担当者別の統計 — **目的（誰宛で未処理か）に要らない**
- 文書の要約・タイトル — **path から開けば分かる**
- 優先度・重要度 — **判断であって記録ではない**
- 2DER の領域データ（DE / 発話 / task の中身）— **MGR §4-2 で禁止**
- 過去の `CC_*.md` の移行 — **前向きのみ（MGR §4-5）**

| **F1** | **書き忘れると台帳が現実とずれる。** ずれた台帳は、走査より悪い（信用できないため） | **移行期のあいだ、状況表が「台帳の `DOC` 行数」と「`CC_*.md` の実ファイル数」を並べて出す。** **一致しなければ、それが分かる。** ★**これは台帳の列ではなく、状況表の1行である。** **MGR の裁定が要る**（延長に当たるか） |
